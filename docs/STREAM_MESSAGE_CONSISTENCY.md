# Predict the next message, not its binary transport header

`OversightBroker::require_stream_message_consistency` fixes an exact existing `StreamProfile` as the event domain before any forecast or proposal. `ConsistencyEventDomain::PayloadPrefix` remains the unchanged default. The new domain uses the original `ReleaseFrame` decoder and `ForecastModel::event`: it tests the registered prefix against only the newly proposed UTF-8 message. A valid explicit finish is a negative event. Previously confirmed messages and binary headers do not become new samples. Each `ConsistencyObservation` retains its event domain.

This is a distinct calibration contract. Probabilities calibrated for raw payload prefixes are not thereby calibrated for message prefixes. The method does not change coefficients, infer calibration, refresh the lifetime alpha, alter the activation source, or provide a disable/rebinding operation. The bound domain remains in the original consistency state, outside actor checkpoints. Quiet evidence still needs the original exact policy, congress, human approval where configured, and effect gate.

The entire frame and exact profile must decode before classification. An uninterpretable release marks coverage lost and retains its unanswered forecast; it is never recorded as a negative event. Validly framed proposed messages still count before downstream admission, including exact denials and unavailable policy evidence. This is classification of the proposed message, not proof that its prior history or target will pass the independent publication checks. The original likelihood-ratio implementation and its threshold are unchanged.

Six unit regressions pair raw-prefix controls with message-aware classification, prior-message exclusion and explicit finish; reject every truncation and foreign profiles; prevent late mode changes; preserve denied and refused samples; retain unknown outcomes on malformed releases; and require congress after a valid negative message. These are added source tests, not executed results. The consumer is the original pre-action consistency gate, closing the gap between plan sections 8.7 and 12.7. Trained-model calibration, source authentication and production qualification remain unestablished. No dependency or existing assertion is changed.
