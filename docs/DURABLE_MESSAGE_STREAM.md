# Durable, independently reviewed message streams

`FileOversight::create_stream(directory, profile, stream_profile)` selects the existing complete-message stream endpoint for a new durable oversight domain. The existing independent resource contract must identify these semantics. Nonempty replacement bootstrap payloads refuse rather than becoming unreviewed audience history. Stream profiles are the original bounded `StreamProfile`; the native endpoint reserves capacity for an explicit finish operation.

The first journal event (new outer tag 24) fixes the stream profile and installs the ORIGINAL mandatory first-publication guard. Any prior accepted event, including a clock, guard, fence or another stream marker, permanently removes bootstrap custody. No public live mode-change API exists. Machine construction temporarily retains one bounded bootstrap-profile clone until its first accepted event; subsequent replay, review, source, governance, effect and accounting operations remain the original implementations.

`stream_message_spec` and `stream_finish_spec` delegate to the original broker builders. They are unreviewed ActionSpec data, not effect permits. The frame includes every confirmed previous message, its boundary and the entire new UTF-8 message. Units charge the whole execution-bearing frame, not just new audience bytes. Submit through the existing proposal/actor interface, run the original whole-input congress, obtain the separately issued human key, dispatch, then use guarded publication and reconciliation. Finish is itself a reviewed effect. Cancellation, source loss and timeout do not invent a finish or erase previously disclosed messages.

`stream_snapshot()` distinguishes endpoint-published history from the broker's receipt-confirmed prefix and exposes the original pending attempt. New work is blocked while that attempt is unresolved, even when its bytes are already in the canonical publication. Duplicate first-publication calls recover the original endpoint result, not another appended message. Missing or changed evidence seals only the current request, and the charge remains until original reconciliation acknowledges the nonexecution outcome.

`open_stream` pins the independent stream profile before cleanup or recovery writes. It then performs the original fence and key withdrawal: saved published history survives, but old sendable envelopes never return. An executed but unacknowledged message can be reconciled; an undisclosed recovered request remains query-only and may be explicitly sealed. `read_stream_publication` validates and reconstructs a complete canonical image without acquiring a writer, invoking a provider or changing clocks. The ordinary open API also preserves recorded stream semantics, but does not independently assert an expected stream contract.

Seven public integration tests cover cumulative UTF-8 disclosure, mandatory two-key/guard paths, explicit finish, distinct publication/confirmation cuts, idempotent endpoint outcomes, changed evidence, dispatched charges, execution and nonexecution recovery, independent profile checks, changed message boundaries, message bounds and human-key expiry. Three unit tests cover first-event custody, native capacity constraints and exact/truncated/out-of-bound stream profile encoding. These are source tests, not passing execution evidence.

This is a Unix filesystem reference profile for plan §8.7 and the existing evidence/publication/recovery path. Publication means bytes in the canonical local journal, not receipt by an external audience or a token/tool-call streaming transport. A whole message is a disclosure boundary, not a claim of semantic safety. Operator storage, source truth, clock fidelity, helper independence and human authentication remain assumptions. No new dependency, evaluator, rights ledger or policy implementation is introduced; existing event bytes retain their encodings.
