# Atomic composed-guard bootstrap

`FileOversight::create_guarded(directory, profile, guards, credential_registration)` validates the original configured gate transitions in memory and places all of them in the first canonical image. It does not first publish an unguarded owner and then enable gates through a series of separately acknowledged updates. Stream mode remains the first-event-only original contract. Without stream mode, the original first-publication guard is always enabled explicitly.

The constructor composes file-source capture, model identity, campaign-required governance and credential-mediated publication without replacing their evaluators or authority. Source/identity/campaign/credential bootstrap events retain their existing encodings. The returned `FileOversightRoles` supplies the human reviewer and, where configured, the identity observer and policy governor after the sole canonical replacement acknowledges. No live-owner role getter exists. The roles must still be assigned to separate custodians, and no clock, source observation, matching identity, campaign approval, effect key or provider secret is supplied by bootstrap.

A credential policy assertion is insufficient: `FileCredentialRegistration` must provide a loaded perimeter inventory and route binding accepted by the existing `FileCredentialPolicy::resolve`. The resolved policy must equal the requested policy. Missing, extra or inconsistent credential registration refuses. The resolver is shared internally, not copied into a second admission implementation. No secret credential bytes enter the initial image; actual broker/provider pairs are bound separately by the existing API.

Invalid native combinations refuse before creating a directory. Once storage creation begins, filesystem or encoding errors can leave a private but incomplete directory; no owner or role is returned. An unacknowledged rename may leave the complete guarded image visible. There is never a deliberately published partially enabled image. `open_guarded` can recover a complete canonical image using the independently retained contract; it never promotes a staging file when canonical data is absent. Creating over an existing directory is rejected, not treated as an upgrade or a reset.

Five public integration regressions cover all guards from startup through real evidence files, identity measurements, full-input congress, separate human approval, credentialed message publication, policy promotion and same-owner role recovery; invalid native configurations; original perimeter resolution; existing-owner preservation; and explicit black-box guarded publication. A unit regression exercises the five original canonical replacement barriers on first-image publication. Together with the recovery tests, the source additions, including the numerical composition cases below, include 19 regression functions and two compile-fail doctests. None were executed in this environment. RCH remains absent; Rust compilation, formatting, Clippy and tests require independent frozen-source verification.

This is reference-profile functionality for plan sections 8.8, 16.4 and 22.7 and the composed identity/source boundary. It provides no cryptographic attestation, hardware power-loss qualification, deployment isolation, measured latency or production admission. Existing legacy entry points remain explicit separate profiles. No new dependency, journal format, original test assertion, Beads state or qualified count changes.

The same atomic initial image can also include `FileGuardSet.decoder`. This uses the original immutable SafeTensors/monitor/sampler configuration and `DecoderEvent::Enable`, not a second numerical host or new event format. Two additional integration regressions compose every guard with numerical execution across restart and a second credentialed message, and pair valid continuation with refusal to resume a held numerical run even after fresh identity and role recovery. All new Rust execution remains pending because RCH is unavailable.
