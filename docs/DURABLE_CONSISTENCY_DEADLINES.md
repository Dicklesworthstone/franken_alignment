# Durable containment when an actor stops answering forecasts

`FileOversight::action_consistency_deadline` returns the exact pending basis. `FileConsistencyObserver::expire_forecast` requires that basis, the current journal revision, the original observer role and an explicit elapsed tick in the registered host clock domain. `FileSupervisedDriver::next_consistency_deadline` exposes only still-covered pending forecasts for scheduling; `expire_consistency_forecast` uses the separately held observer and keeps original helper maintenance. The driver must be scheduled even without incoming actor bytes. No event loop, hidden task, independent watchdog or clock provider is introduced.

Early checks write nothing and do not renew the saved clock. Stale or changed bases, foreign roles, old revisions and backwards time refuse before poisoning. Once a matching deadline is due, the live owner becomes unavailable before event-capacity checks, encoding, historical replay or storage. The original shared canonical commit records the clock observation, missing coverage and native consistency-stop cleanup together. An outer error is unacknowledged; a nested native error is recorded with lost coverage, not discarded. On a new stop, the existing cleanup pauses inference and withdraws identity, campaign approvals, human keys and sendable envelopes. Dispatched effects remain charged until original endpoint reconciliation.

An exact recorded timer retry returns its original result from memory-only replay without writing or renewing time, even after later history. It does not revive old roles or restore a current success. A missing canonical timer is not evidence the forecast was answered: original recovery retains the pending forecast and treats its outcome as lost coverage. Source interruption is neither consulted as permission nor cleared by expiration. Previous ordinary time records retain their original semantics; replay never retroactively turns them into expiry events.

The new input is consistency-family subtag 6 followed by seven big-endian u64 values: attempt, forecast actor revision, forecast authority epoch, capture sequence, creation tick, expiry tick and observed tick. It imports no score, lost-coverage Boolean, stop receipt or action outcome. Exact pending equality and time ordering are rechecked by semantic replay. Configuration versions one through four and all earlier event bytes remain unchanged. Silence contributes no likelihood factor, creates no request-book entry, and never asserts what the actor would have done.

Three unit regression functions exercise all five original Store replacement barriers, exact event capacity with early/stale controls, an independently assembled wire vector and every truncation, semantic rejection of early/substituted timers, old-time compatibility, source-interruption preservation and read-only exact retries. Three public regression functions plus one separately re-executed child fixture cover real two-key publication after an early timer, role/revision rejection, canonical recovery with no invented request, and an actual actor process becoming silent after a dispatched request. The process test contrasts timely completion with silent executed/unexecuted cases: deadline containment closes ingress and requests termination without source/clock reads, while only the original drain settles effects. The child is an analytic protocol client, not model inference or sandbox qualification. One compile-fail doctest rejects timer-to-permit conversion.

RCH targeted tests and the full xtask gate are attempted, but rch is unavailable and compilation, formatting, Clippy, tests and doctests remain unverified. Source identity, patch and whitespace checks do not qualify runtime behavior. No dependencies, pre-existing test assertions, Beads states or production gates change. Clock provenance, file integrity, host scheduling and process isolation remain external assumptions. An unrecorded timeout does not magically become an authenticated historical event after a crash.
