# Durable monitored-decoder checkpoint resets

`FileOversight::capture_decoder_checkpoint` pairs the current quiet, nonempty numerical prefix with the ORIGINAL authority checkpoint, and commits the capture in the existing journal. It does not accept checkpoint bytes, model parameters, a sampler seed, a monitor result or a saved permit. A handle is immutable identity, not authority. Exact capture retries retain the original prefix rather than capturing the current continuation.

`reset_decoder_checkpoint` consumes a supervisor `FileResetRequest` plus a numerical replay budget. The existing `OversightBroker::reset_hosted_decoder` recomputes and re-reviews every saved token, compares exact cache/logit/sampler state, advances stream provenance, narrows authority, increments the original incident count and cancels only undispatched work. Lifetime computation and monitoring costs do not rewind. The durable wrapper retains native successful AND refused reset results by exact operation identity. An exact retry returns that historical result, not another replay or incident; changed checkpoint, budget or control fields conflict. Both capture metadata and reset-result retention are bounded by the existing `MAX_CHECKPOINTS` cap in addition to the journal's byte/event limits.

A reset that was admitted for replay retires old automatic and human effect keys and live review sessions in the same canonical replacement. The original broker alone decides refunds. Previously sent envelopes, unknown charges and endpoint outcomes remain for guarded sealing and original reconciliation. Reset does not prove nonexecution or erase a published message. Source interruption does not prevent this restrictive supervisor operation, but reset cannot clear the source interruption latch.

Decoder journal subtag 4 stores capture/reset INPUTS and comparison-only post-operation witnesses. Prior tags and encodings are unchanged. Replay reconstructs each native pair from its original capture, reruns each numerical reset and compares exact numerical/actor state, recovery costs and original result fields; no witness is decoded into a running actor or approval. The original reset ceiling is a subset of the requested targets and its membership is compared as such. Original policy, source, identity, congress, human-key and first-publication requirements remain in force.

On recovery the original fence withdraws old keys, and the decoder stays paused. `decoder_checkpoint` reacquires a new owner-branded historical handle; old handles are rejected. A fresh clock is required for a new reset. Even a successful reset of a recovered held continuation leaves the recovered owner paused until explicit `resume_decoder`. Identity and source requirements must independently be satisfied. Reaching the original incident threshold suspends instead of restoring; neither a checkpoint nor a fresh request can undo that suspension.

Once a new numerical reset starts, failure to encode or persist its result, or a caught unwind, leaves this owner unavailable. It cannot continue using the old eligible state after silently discarding replay failure. Recovery consults only the actual canonical image and performs the existing fence; no unacknowledged receipt or token is returned. These are synchronous reference transactions and whole-history numerical replay, not latency, allocation or hardware power-loss guarantees.

Six public integration tests cover exact next-sample replay, held-state recovery, capture/reset idempotency, explicit recovery pause, old-key rejection, unknown-effect accounting, new two-key publication, native budget refusal and numerical witness tampering. Two unit tests cover the new input codec, all truncations and invalid bounds; one compile-fail doctest rejects checkpoint-to-permit conversion. These are source additions, not passing Rust execution evidence. The RCH verification attempt exited 127 before compilation because `rch` is absent; compilation, formatting, Clippy, tests and doctests remain pending.

This advances plan sections 11.2 and 11.10 / FA-108 using the original registered CPU reference decoder and containment logic. It does not qualify a production restart profile, authenticate external model/clock/storage roots, change dependencies, close Beads or promote production gates. Tiny deterministic fixtures do not establish trained-model behavioral forgetting or incident-detection effectiveness.
