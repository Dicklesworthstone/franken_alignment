# Original learned evidence in the helper congress

## Source and consumer

`oversight::learned_host::sidecar` supplies the plan section 10.15 connection
from the ORIGINAL broker-owned learned generation to actual independent helper
input. `begin_learned_sidecar` uses the proposal's already-bound `LearnedEvidence`
and its actual `CheckedLearnedKv`. It does not run inference, fit another codec,
recapture raw cache values, compress again or accept a caller-selected source.
The original audit's codec, evaluation origin and retained residual inventory
cannot change. The source is the latest accepted position across all K/V taps;
the owner-attested token prefix is NOT a full historical activation trace.

The existing `SidecarCongressPlan` creates the whole-input committee packet,
including the original frozen action, helper-specific question and exact coarse
checked-source bytes. Identity, residual priority and bounded disclosure costs
are explicit supervisor choices, not proof of external authenticity or empirical
helper quality. Initially no optional residual is disclosed. Original input
retention, helper replication and per-plan budget checks remain active.

## Optional versus mandatory review

A trusted supervisor may call `enable_learned_sidecar_requirement` before the
owned generator's FIRST token and before any proposal. This fixes mandatory
sidecar review for its lifetime; there is no disable or weaker replacement.
Existing optional learned and residual configurations retain their behavior.

In mandatory mode the SAME decoder gate used at review start, permitting review
application, authorization, human-approval request and dispatch additionally
requires the current input revision to have been produced by the learned-sidecar
path. Manually supplied text-only or even byte-identical packets cannot register
that source connection. No redundant input/approval ledger is introduced: only
bounded revision markers refer to the original monotonically versioned inputs.
Each proposal can begin one disclosure plan, only as its first input. Withdrawal
or replacement cannot reopen the plan or replenish its budget. Optional packet
inspection never means permission; congress, human keys, witnesses, epochs,
current-source checks and the original endpoint still decide effects.

The source-only preparation seam is private to the broker. It exists because
constructing the first helper packet must validate the proposal source before
that packet exists. All existing permitting callers retain the complete check.
Known source changes, later holds, suspension, deadlines, foreign broker handles
and changed input revisions refuse. Historical handles retain their old evidence
without presenting it as current. Source loss after dispatch still requires
ordinary endpoint reconciliation; this addition never refunds unknown effects.

## Mutation and cost boundary

The planner and initial packet are prepared before the original input recorder
commits. The bounded revision-marker map and input copies are allocated before
that commit; only infallible moves follow successful recording. Failed packet or
input-capacity admission leaves no registered sidecar and no consumed revision.
One independent new attempt may use the same source, but its retained input is
charged again. There is no global experiment escrow or physical-memory claim.
The handle shares existing checked-source evidence and owns encoded helper
input; it does not add decoder products or generation telemetry work. Encoding,
copying, retained metadata and codebook bytes still have cost. No measured
speedup, network authentication, durable recovery or native CLI is claimed.

## Abstention-driven coarse-to-exact review

`refine_learned_sidecar` accepts a completed, unapplied ORIGINAL review belonging
to this broker, attempt and exact current input revision. The controller must
have independently observed at least its completion time, and the action must
still be unexpired with its original source current. The existing planner alone
selects the next frozen retained residual and applies the round, residual-byte
and total committee-byte budgets. No codec change, raw-cache fallback, generated
sample or second numerical audit occurs. Missing workers, an empty authorized
priority list and budget exhaustion remain explicit nonpermitting outcomes.

A refined packet and its provenance marker commit through the same original
input recorder. Planner state and marker allocations are staged first; failure
of the broker-wide cumulative input cap cannot consume a residual or make an
unrecorded richer packet current. Both the marker and handle move to the new
input revision only after success. A retry of a refused recording meets the
same recorder refusal, while retrying an already successful refinement with its
old review is stale. The planner cannot be reopened to reset its spending.

New bytes invalidate the old approval basis. Even a completed Allow over the
coarse packet cannot approve its replacement; a fresh independent congress and
any installed human key are still required. Ordinary review entry points check
the mandatory marker as well, so callers need not use a special permission path.
Historical source and packet objects are unchanged. The latest-position scope,
original source lineage and one-use effect accounting remain unchanged.

Seven additional integration functions cover the actual coarse-abstain-refine-
fresh-review-two-key-publication path, stale coarse Allow, exact and one-less
budgets, missing verdicts, empty priority, foreign/other-attempt reviews, changed
sources/inputs, completion-time/deadline boundaries and REAL broker input-budget
exhaustion by recording bounded inputs on another attempt. The capacity test
first demonstrates a funded original planner control, then verifies repeated
recorder refusals leave both the handle and mandatory marker at the old input.
No private cost counters or original test assertions are altered. There are now
fifteen authored integration functions and three compile-fail examples; all
remain unexecuted pending a fresh successful RCH gate.
