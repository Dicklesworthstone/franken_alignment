# Computed model identity in learned publication

FA-118; plan section 7.10; founding synthesis FS-07.

The learned operator can require a fresh identity measurement from its actual
imported numerical owner before beginning a publication request. It executes the
original registered stimuli and tapped activations against an independently
provisioned passport. A successful measurement still needs separate native
installation, helper Congress and fresh human approval before publication.

## Select the complete registration

Wrap an existing learned recipe in `fa.learned-identity-publication/1`. This
closed envelope has exactly three fields: `schema`, `identity` and `recipe`.
The `recipe` field contains the complete original version-1 through version-6
recipe, or the existing joint-credibility envelope around that recipe. Canonical
composition is identity(legacy) or identity(joint(legacy)); reversed, repeated
and unknown wrappers refuse.

The `identity` object has this exact shape:

```json
{
  "passport": "/operator/identity/passport.bin",
  "policy": {
    "observer_id": 71,
    "timeout_ticks": 1000,
    "validity_ticks": 10000,
    "max_checks": 64
  },
  "check": 1,
  "measurement_sequence": 1,
  "scalar_products": 100000,
  "observed_manifest": "/operator/identity/observed-manifest.bin"
}
```

Passport and manifest files use the original bounded binary codecs in
`activation::identity::wire`. Provision the passport independently of the model.
The operator accepts neither precomputed matching decisions nor caller-supplied
anchor frames. The independently observed manifest is a separate live input,
read after deadline and authenticated Stop checks. An incorrect manifest reaches
the original manifest-mismatch path without anchor computation.

`with_required_computed_identity_registration(FileIdentityRequirement)` freezes
the complete passport and all four policy fields into the learned configuration.
The original registration codec binds manifests, stimuli, anchor intervals and
policy together. This covers ordinary, raw-predictive and owned-predictive owners,
including topology mediation. Numerical, source, predictor, continuation and
joint-credibility selections remain part of the same exact configuration.

Check ID, measurement sequence, work allowance and observed-manifest path are
per-attempt inputs. Nonzero identifiers, policy bounds and original measurement
budgets are enforced. The entire recipe retains the 64 KiB byte ceiling and
aggregate item/string limits, with only the fixed additional envelope depth.
Old unwrapped and joint-only recipes retain their behavior and configuration bytes.

## Original custody and cooperative measurement

Creation publishes the complete native guard inventory, learned owner, terminal
reserve and selected predictor in one first canonical image. The operator keeps
the original unique identity observer alongside its human and predictor roles.
Live recovery returns fresh roles through the original guarded recovery path;
an identifier cannot manufacture observer custody.

Each request refreshes required source evidence and native time, completes
credibility qualification and prepares admitted numerical continuation before
beginning the identity challenge. `FileComputedIdentityRun` consumes the separate
observer and advances at most one original stimulus token per step. Frames remain
private until the original complete-roster result is acknowledged in the journal.

The complete owner revision stays pinned during preparation. Clock reads and
authenticated peer admission remain available; source refresh and other journal
mutations cannot alter the measured state. Stop and deadline interruption cancel
the preparation before Stop-driven mutation. Completed work stays in retained
run history, and only original cancellation or acknowledged commit returns the
observer. Setup refusal returns its original observer and closes its pending
challenge without inference. A committed measurement refusal retains its actual
completed work and withdraws only its own still-current challenge basis, leaving
any successor untouched. Storage failure retains the native poisoned-owner rules.

Computed commit and `apply_identity_check` remain separate. After acknowledged
completion and peer checks, installation observes a fresh native tick. A result
that expired in the interval stays historical and cannot install matching
eligibility. That mutation occurs after the prepared cursor is committed.
Neither operation supplies an actor release, forecast, Congress decision or
human key. Generation and publication retain all original source, time,
qualification, forecast and two-key gates. Actual anchor mismatch uses original
incident and containment behavior; there is no manual-frame fallback.

## Recovery, historical commands and resident sequences

All recipe modes load the independently supplied registration, including receipt,
audit and terminal modes. Changing or omitting it changes exact recipe identity
and refuses before cleanup or role provisioning, even if the history contains no
measurement yet. Historical commands do not read a fresh observed manifest or
current helper/capsule inputs merely to inspect or finish original custody.
Primary model, tokenizer, fit and forecast assets required by replay remain required.

Recovery withdraws old matching eligibility. Fresh computation can inspect a
paused owner, but cannot resume it, refund numerical or forecast work, reset draw
counters, revive old effect keys or retry an ambiguous effect. Joint credibility
and computed identity remain independently enforced.

`serve-learned-generated` requires the same complete registration and exact
numerical configuration throughout a resident sequence. Each attempt needs a
distinct check ID and strictly increasing measurement sequence. Inconsistent
selections or a sequence beyond the original check allowance refuse before the
runtime, clock, sockets or authority store open. The invocation retains its
observer and run history across entries; finite native budgets and the existing
invocation-wide Stop operation remain in force.

## Scope and trust boundaries

This integrates the existing finite native measurement into the learned operator.
It does not authenticate passport provenance, sign manifests, attest the serving
host or establish detection of every possible parameter substitution. Provisioning,
manifest commitments, clocks and operating-system custody retain their trust
assumptions. Fixed test models exercise real computation and enforcement, not
empirical detector quality.

Cooperative preparation and cancellation accounting are process-local. No durable
partial-token resume, preemptive inference or crash-surviving lifetime computation
escrow is claimed. Original history replay remains synchronous and bounded.
Passport signing, randomized audit-floor scheduling, full evidence-generation
propagation, H19 discrimination and the complete FA-118 packet remain open.
