# Native consistency incidents in durable terminal containment

`FileConsistencyConfig::with_terminal_stop` binds the original `ConsistencyStopPolicy` to the durable predictor before any work. Atomic predictive and mediated startup replay that native enable operation in the first canonical image. The policy handles both actual likelihood-threshold crossings and recorded coverage loss. There is no caller-supplied trigger, threshold replacement, alpha refresh, live mode switch or implicit policy upgrade. Configurations without this option preserve the original hold-only behavior.

The version-four `FACPRED\x04` envelope contains one length-prefixed complete v1/v2/v3 configuration followed by the policy ID, generation and stop-operation ID as three big-endian u64s. Nested stop envelopes refuse. Builder order with hosted-residual and message-prefix modes produces identical bytes. Original encodings, public configuration parameter structs, action journal tags and wire commands are unchanged. The existing configuration-size ceiling applies. Guarded recovery compares the complete configuration before numerical replay; it cannot quietly omit or substitute the stop policy.

The original broker derives incident cause, sample history and local stop receipt. After a forecast, proposal or explicit capture loss installs a stop, the durable machine performs the existing manual-stop cleanup within that SAME canonical replacement: decoder pause, identity withdrawal, policy-campaign revocation, human-key withdrawal and disposal of sendable envelopes. Refused proposals still retain the category already consumed by the original predictor. Recovery fences and numerical operations keep their existing cleanup paths. Repeated observations or an already-stopped owner do not repeatedly perform this new cleanup; an earlier different stop operation retains its own receipt identity.

Stopping cancels only eligible undispatched work. Executed and unresolved dispatches remain charged until the original endpoint drain reconciles their different outcomes. An unanswered forecast during recovery remains pending and becomes coverage loss; under this configuration that recovery fence also installs the native terminal stop. Clean quiet recovery still permits fresh forecasts and two-key review. Neither case resets lifetime evidence or restores old roles or effect keys. Explicit loss also uses the pre-encoding unavailable latch, so storage/capacity failure cannot leave an older permitting live owner usable.

`consistency_stop_policy` and `consistency_stop_incident` expose acknowledged native evidence and refuse on an unavailable owner. `read_predictive_stop` uses the original exact predictive-guard checker and complete canonical history beside a locked or faulted owner. It acquires no writer, cleans no staging, samples no new time and returns no role. Its report keeps the first native incident separate from later publication/accounting state. A lost crossing write can leave either an observed crossing or an unanswered forecast on disk; recovery must preserve that distinction instead of inventing a sample. Mediated owners continue to use their exact mediated recovery and existing canonical reader; the new predictive reader does not bypass their additional graph contract.

Thirteen regression functions plus one separately re-executed analytic actor fixture cover exact legacy bytes, all builder orders, malformed/truncated configuration, maximal coefficients, default-hold versus terminal-stop behavior, original sample/refusal/retry accounting, independent human and campaign key withdrawal, identity withdrawal, executed/unknown/unsent liabilities, clean and unanswered-forecast recovery, actual owned decoder forecasting and publication, and real direct-child termination through the existing supervisor without source reads.
