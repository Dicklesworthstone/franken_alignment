# Durable replay-approved policy promotion

`FileOversight::enable_policy_campaigns(revision, limits, max_campaigns)` installs the original broker's mandatory policy-campaign mode before any proposal or actor request and returns a separately held `FilePolicyGovernor`. The roles and review handles are under `persistent::observed::governance::campaigns`. A configured owner cannot bypass the mode with ordinary `replace_policy`; legacy unconfigured owners retain their explicit original behavior. The standalone replay report is not an approval.

`request_policy_campaign(revision, &PolicyUpdate)` replays the entire original current-policy corpus, including exact denials and applied congress reviews. The governor receives an immutable historical review. Its `approve` method requires explicit acceptance of observed newly-reviewable cases and refuses campaigns requiring unseen observations even when that flag is true. Approval, rejection and revocation are journaled inputs to the original native gate. A `FilePolicyPromotionPermit` is returned only after acknowledged storage; neither that key nor the governor is cloneable, and querying an approved campaign cannot regenerate a lost key.

`promote_policy_campaign` checks the native exact candidate and full history stamp again. A newly recorded denied proposal can invalidate approval even without changing the control sequence. Promotion invokes the original policy transition, cancels only its eligible undispatched attempts, withdraws outstanding human effect keys, and records the existing `PolicyUpdateReceipt` in the SAME canonical replacement. The original policy-history book supplies current_policy and historical retry receipts. Admitted/unknown effects retain their charges and envelopes until original endpoint reconciliation supplies the outcome. Subsequent work still requires congress approval and the separate human effect key.

Recovery and terminal stop revoke every pending or approved campaign. `open_with_policy_governor` performs normal exclusive recovery before provisioning a fresh governor; it refuses an unguarded journal rather than enabling it late. Old process-local roles and promotion keys do not match the new owner. A possibly persisted promotion is reconstructed as historical Promoted state, never executed a second time. Exact request/promotion retries recover evidence or an existing receipt, not fresh authority. A historical FilePolicyCampaignReview does not mutate as later transactions occur: re-query policy_campaign for its latest disposition.

The new journal family uses outer tag 23 and bounded enable/request/approve/reject/revoke/promote variants. Existing event encodings are unchanged; policy syntax reuses the original bounded codec. Native replay/campaign limits and the original journal/recovery-capacity limits remain in force. Request metadata additionally retains at most max_campaigns bounded PolicyUpdate values. The existing transaction mechanism replays the journal in RAM and replaces the canonical file; no new ledger, executor, dependency, signature primitive or performance claim is introduced.

Nine public integration tests cover actual new-policy effect execution, raw-replacement refusal, relaxation and shadow handling, stale history, role isolation, one-shot keys, idempotent receipts, recovery, capacities and unresolved-effect accounting. Five unit tests exercise all five replacement barriers for both approval and promotion, invalid promotion replay, stop, and codec/truncation cases. Two compile-fail doctests cover non-cloneable roles/keys. These tests are source additions, not passing execution evidence.

This is a Unix filesystem reference profile for plan §22.7 / FA-130 and the no-implicit-widening contract. Governor custody and operator storage remain assumptions; no authenticated evaluator identity, cryptographic approval, anti-rollback guarantee, hardware power-loss durability or production runtime admission is established. Rust compilation, rustfmt, Clippy, tests and doctests remain unexecuted: RCH was attempted but is absent (exit 127). No Beads or production qualification gates are promoted.
