# Explicit continuation of a held learned native review

This is the retained-evaluator continuation of plan §9.8 HoldEffect. It uses the
original source-bound learned sidecar and its already provisioned native model
reviewers. The original generated Message, cumulative output, numerical actor
work and sidecar packet remain unchanged. A separately selected operator may
request the next unused review slot; the request does not supply new models,
new packet bytes, a verdict, a clock or effect approval.

## Provision the complete review before it starts

Select the original finite `convene_port(queries, operations)` grant before the
held native round completes. Keep its nonclone custodian alive. The original
`FileNativeDriverLaunch` must already contain the complete native roster and
strictly ordered round windows, including an unused successor. A one-round
sequence has no successor capacity.

The complete native reservation, poll limit, per-evaluation limits, sidecar
disclosure plan and action deadline are admitted once. The next round consumes
that reservation. It cannot choose another helper, skip a slot, replace the
packet, extend a window, reset an evaluator, or renew the native poll allowance.
An unused roster remains reserved work, not a refund.

Automatic residual refinement retains its existing contract. When the original
sidecar buys a richer packet, its existing fixed schedule can advance through
the original refinement path. An applied Hold without refinement instead
retains its terminal native review and unused models for an explicit request.
It starts no successor by itself.

## A live retained owner is necessary

`FileNativeSupervisedDriver::held_successor_round()` observes the exact next
original slot while its successful Hold, action, learned source, sidecar packet,
input revision, policy epoch and original deadline remain current. The wrapper
retains the closed publication job and completed numerical history. Routine idle
polling preserves them and performs no source acquisition, clock read, model
quantum, queue selection or grant renewal.

The original supervisor advertises a private offer for that request, held
predecessor and next reserved round. Its custody marker is weak: the grant,
operator handle, queued record and taken ticket cannot keep the evaluator owner
alive. The original fixed round ID is the only exception to the normal exclusion
of already reserved worker IDs. Other reserved or arbitrary IDs remain refused.

The usual Tower `next` and `convene` documents and finite query/operation
accounting are unchanged. Next, admission and ticket consumption each recheck the
exact live offer and acknowledged predecessor. A source change, numerical
advance, changed input, Stop, cancellation or authority change cannot reuse an
old successful Hold. A failed later round cannot borrow an earlier Hold.

Selecting a grant after the held round completes does not retroactively
advertise an offer. Handoff, cancellation, failed continuation or loss of the
retained wrapper withdraws the weak custody. A historical packet, completed
receipt or generic file driver cannot recreate it after recovery.

## Consume one original slot

The retained wrapper exposes:

- `held_successor_round()`: inspect the next eligible fixed slot without work.
- `take_pending_convene()`: take an independently admitted one-use ticket for
  that exact slot; return no ticket when the retained review is ineligible.
- `convene_from_policy_file(source, ticket, clock)`: reacquire the original
  policy-only file source, open the next original native round, and return
  bounded source observations and current progress.

The last operation first checks the ticket, owner, held basis and original job
before invoking a source or clock. If topology mediation was selected, it uses
the same retained topology custodian and spends its original refresh before
policy capture. A retained certificate cannot replace the actual source
custodian.

Fresh policy evidence must preserve the exact original learned packet and
source binding. A caller-supplied helper context or changed policy snapshot
cannot rebase the packet to make the held output eligible. This route does not
prepare another sidecar or replenish disclosure capacity. Its scope is a fresh
review of the existing packet using the next preselected evaluator.

After capture, the wrapper checks the current packet, actual clock and next
fixed window again. It opens the original leased round through the existing
durable Begin and returns the same publication job to Reviewing. Opening the
round evaluates no native model quantum. Subsequent original cooperative steps
consume the remaining cumulative native poll allowance.

Pending means admission only. Opened means the original Begin succeeded.
Failure or abandonment keeps the operation and its round ID spent. An admitted
capture/clock/launch failure retires the remaining native evaluators and weak
offer; restoring a file or reconnecting cannot relaunch that handoff. Earlier
work records, reserved cost, packet and completed review history remain
inspectable.

## Preserve independent publication and termination

Only a newly completed original Continue can make the original job ready for
the existing publication path. It still needs a fresh independent human key,
current final source checks and the original guarded endpoint. The new round
cannot reuse human approval or settle an unknown effect.

The original Stop, cancellation, source-interruption and deadline laws remain
in force. Native wrapper handoff revokes any queued or taken ticket even though
it returns the terminal review history. The generic file/socket review launcher
explicitly refuses learned sidecar custody, including a ticket originating from
a valid native offer.

Supported core owners have the compulsory source-bound learned sidecar and no
raw or owned forecast/consistency contract. Plain and cumulative text owners
share the same original packet law; selected topology mediation keeps its
separate source obligation. Process-helper sequences and predictive owners
remain outside this retained-native continuation. They are not silently
converted to native model reviewers.

## Select continuation in a live service

The live `create-learned-generated` and `serve-learned-generated` commands use
the existing independent operator options:

```text
--operator-profile OPERATOR_PROFILE --tower-generation 41
```

Select a positive finite grant in the existing
`fa.tower-operator-service/1` profile:

```json
"convening": {
  "queries": 32,
  "operations": 2,
  "authority": "convene_held_review"
}
```

The complete profile still needs its original scope, independently authenticated
operator identity, supervisor identity, socket and finite transport/runtime
limits. Select it before native review starts. Structural profile admission does
not establish learned eligibility: the actual loaded recipe must use native
model helpers with no raw or owned pre-output forecast. Process helpers and
predictive recipes reject the selection before clock, source, store or listener
startup. Every selected entry of a resident sequence must satisfy that admission.

Use a progressive v2-or-later learned recipe with multiple explicitly selected
`native_review.round_ids`, its matching `sidecar.budget.rounds`, priority ladder
and sufficient original helper allowance. A v1 single-round recipe cannot
supply a successor. The complete schedule and every native evaluator are
provisioned once before the initial review. A selected grant cannot add a round
or reserve more native work after the result is visible.

At the exact original request address, send Tower `next` with
`{"action":"convene_held","round":"8"}`, substituting the exact next
preprovisioned round. Integers in Tower documents are canonical decimal strings.
Inspect the complete generation-bound action and explicitly submit its returned
`convene` document through the authenticated operator exchange. The existing
protocol distinguishes Pending admission from an actually Opened round; it does
not accept a replacement recipe, packet, verdict or caller clock.

The service retains the same native wrapper while waiting. It pumps the
original finite operator endpoint, authenticated Stop and actor cancellation,
without spending a native evaluation poll. The successor's commit and reveal
windows stay fixed at initial launch; admission must reach the original wrapper
before that commit deadline. Expiry, revocation or loss of eligibility ends the
wait without opening another review. Reconnects never slide a window or renew a
grant. A consumed source/clock/launch failure retires remaining native custody.

The common review loop serves single live requests and resident plain or
cumulative sequences, including newly selected requests in supported governed
or recovered suffixes. It does not revive historical held requests. Recorded
`--resume` and receipt-service grammars independently refuse the live operator
options. A later Continue still enters the existing fresh human decision and
guarded publication path.

See [live learned operator selection](LIVE_LEARNED_OPERATOR.md) and
[resident learned publication](RESIDENT_LEARNED_PUBLICATION.md) for complete
command, identity and invocation-lifetime requirements.

## Verification boundary

Eight authored public integration functions use actual fixture learned actor
generation and preloaded native helper models. They cover exact packet and
output preservation, cumulative reservations/polls/history, repeated no-I/O idle
polls, fresh human approval and rejection, wrong or foreign round custody,
source loss and changed input, stale predecessor, Stop/cancellation/handoff,
finite grant exhaustion and an expired fixed successor window.

Five additional service regression functions cover the retained native wrapper
through authenticated Next/Convene and fresh human approval, grant absence and
fixed-window expiry, source loss and cumulative poll exhaustion, independent
Stop with a partial operator frame, and actual loaded process/predictive
admission refusal. Existing closed historical command regressions preserve
receipt observation without live mutation admission.

Synthetic model weights and controlled ballots do not establish detector
reliability, hostile-process isolation or production qualification. Independent
source review covers the exact implementation and tests. The execution workspace
became unavailable before formatting, compilation or runtime tests; the required
RCH runner was absent during preflight. No new syntax, compiler, Clippy, runtime
or full-gate pass is claimed.
