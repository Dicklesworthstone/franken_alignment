# Actor stream intents through the original durable supervision path

`FileActorPort<FileOversight>::submit_stream(request, &FileStreamProposal)` accepts one complete nonempty UTF-8 message, or an explicit finish represented by `message: None`. The intent pins the full target (including its version), expected policy epoch and deadline. The type lives in `persistent::observed::stream`. It is unreviewed actor data, not a permit or a sendable frame.

The existing locked host privately derives the cumulative frame from its original receipt-confirmed stream history. The actor need not reconstruct prior messages and receives only its original `FileActorTicket`. The API exposes no host, clock, evidence provider, helper, reviewer or publication endpoint. New requests still need the supervisor's existing one-shot admission snapshot, then pass the original request book, broker policy, full-input congress, separate human key, guarded publication and receipt reconciliation. The existing restricted Knowledge projection and cancellation behavior are unchanged. A published but unacknowledged message remains OutcomeUnknown to the actor.

Exact retries use the ORIGINAL raw ActionSpec retained by the existing request book, including NotAdmitted requests that never produced a FrozenAction. They never rebuild against today's prefix or policy, consume a new admission snapshot, invoke a provider, or recover a permit. Changed message/finish kind, target, epoch or deadline conflicts under the original request ID. After reopening, an exact old retry can recover its ticket without a newly observed clock or admission snapshot. A weak old port cannot retain the writer lock, and a ticket from another gateway remains withheld. Malformed/stale new intents refuse before consuming the supplied admission snapshot. All bounded checks happen before new frame retention; original frame and request byte limits remain authoritative.

This composes the existing request transaction rather than adding another request or authority ledger. The original request event encoding is unchanged. The added original_spec helper is private to the durable implementation; it is not an actor-facing retained-packet getter. Frame preparation and original submit run without an intervening callback, await or external operation on the same Rc-owned gateway. The public method is an in-process actor API, not a new wire verb, model inference API or transport.

## End-to-end and fault regressions

Four actor regressions cover cumulative message and finish intents, Pending/Unknown/Executed projections, exact retries after prefix movement, changed-identity conflicts, one-shot snapshot preservation, absent-source NotAdmitted requests, weak owner custody, foreign tickets and recovery without a fresh clock. A fifth public regression drives TWO actor message requests through actual nonblocking Unix socket pairs and the existing HelperClient and FileSupervisedDriver. It checks that each worker receives the complete execution-bearing frame, supplies a fixture-selected vote once, obtains the separately issued human key and traverses separate dispatch, publication and reconciliation phases. Reconciliation's provider closure panics if called. This test does not claim real model inference or authenticated worker independence.

Two unit regressions exercise all five original Store replacement fault barriers (Stage, Write, FileSync, Rename, DirectorySync) separately for message publication and receipt reconciliation. An ambiguous publication failure leaves the acknowledged owner at its previous cut and unavailable; read-only inspection may find a newer canonical message. Reopen recovers only the actual canonical history, never a staged message or old sendable envelope. A published message is not appended again; an undisclosed recovered obligation remains query-only until explicit sealing. Reconciliation failure cannot erase published messages or duplicate their charge/refund. Every case retains an already published prefix as its positive control. These are deterministic failure-injection scenarios, not hardware power-cut qualification. One compile-fail doctest checks the actor port has no publication method.

## Verification and boundary

Five public regression functions, two fault-test functions and the compile-fail doctest are source additions, not reported passing execution. The required RCH command was attempted in the editing environment and exited 127 because rch is absent, before compilation. Rust compilation, rustfmt, Clippy, unit/integration tests and doctests remain unexecuted. No dependency, original test assertion, Beads closure, qualified test count or production gate is changed.

This advances the plan's complete-message disclosure boundary (section 8.7) through the actual durable actor/helper/two-key path. Publication still means the canonical local filesystem image, not receipt by a remote audience. Message completeness is not semantic harmlessness. Independent bootstrap custody, operator storage, source truth, clocks, human authentication and helper independence retain their existing assumptions. Production runtime admission, real isolation, external delivery and independent frozen-source verification remain separate requirements.
