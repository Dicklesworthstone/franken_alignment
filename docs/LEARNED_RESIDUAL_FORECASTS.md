# Owned residual forecasts for learned generation

Source integration, not execution-qualified. This connects the existing learned
K/V generation owner to the existing pre-action consistency monitor (FA-111,
plan 12.7). It does not add a predictor, likelihood reducer, ledger, journal tag,
raw-frame importer, approval issuer, runtime or dependency.

## The same consistency monitor, with the actual learned source

Previously `with_hosted_residual(layer)` could bind only the original sampled
residual-monitoring decoder. A learned K/V generator had accepted original
residual tensors but could not supply that owned-source forecast path. The
hosted consistency mode now binds either mutually exclusive original numerical
owner. Binding validates the predictor's exact residual profile, dimensions,
stream and layer before any admitted numerical token. The learned path also
checks lifetime admitted work so a rewound active timeline cannot permit late
source registration.

Construct the learned owner and enable the original consistency configuration
before advancing it. Select `with_hosted_residual(layer)` as before, then use the
existing separately held `FileConsistencyObserver::forecast_hosted_action` or
`forecast_hosted_request` after an accepted token. Both methods accept only the
owner/revision and attempt or request identity, not a frame, probability or
claimed comparison result. The raw-frame API remains refused in this mode.

The learned source is the selected residual in the actual latest accepted
`GenerationEvent`. Its original whole-K/V quiet audit, synchronized actor state,
layer contract, stream, sequence and position must agree. Empty, held, failed or
interrupted state cannot supply a forecast from a previous quiet token. A
restored prefix without an accepted current event is unavailable, rather than
an invitation to synthesize or import one. Original inference is not rerun and
no sampler draw is consumed merely to extract this source. Durable transaction
replay can still recompute historical events according to its existing rules.

This is an exact residual baseline, not a forecast directly from compressed
latent codes. The frozen calibration table and original exact likelihood process
remain unchanged. Predicting the next admitted effect is not a claim to predict
a generated token before the generator has computed it. A registration must be
calibrated for the actual chosen observation boundary and workload; this code
does not establish that calibration or independence.

## One-shot observations and effects

The original monitor owns forecast age, one-outstanding-prediction limits,
sequence floors, lifetime error evidence and containment. Request forecasts
still bind the existing request allocator before the payload is admitted.
Another request cannot consume the pending forecast; an exact historical retry
cannot add a second likelihood observation. The category comes from the actual
original action bytes, not a caller-provided matched Boolean.

Agreement grants no permit. Whole-input congress, independent human approval,
current-source validation and the guarded endpoint remain required. A threshold
crossing still applies the original restrictive result. Generation recovery
still binds the independent learned recipe, replays the original prediction
records, fences old keys and pauses the numerical owner. An outstanding unknown
forecast retains the existing coverage-loss behavior rather than receiving a
new error budget or a replacement observer role.

## Authored verification and limitations

Eight regression functions use the existing original learned numerical and
congress fixture. They compare forecasts with the original predictor on the
actual acknowledged residual; exercise wrong model/layer/dimensions/stream and
late binding; bind external requests and idempotent observation; pass the full
congress/human/publication path; pair likelihood crossing with a permitted
control; withhold an actual monitor-held source; preserve lost coverage on
recovery; and inject all five forecast-write storage barriers. Existing sampled
source and wire/configuration codec tests are unchanged. Synthetic weights and
probabilities are causal controls, not detector effectiveness or calibration.

The targeted RCH command cannot launch because `rch` is absent (exit 127).
Compilation, tests, rustfmt and Clippy are unexecuted. Container execution was
initially unavailable as well; no missing execution is counted as a passing
check. No local compiler fallback, measured performance, qualification or bead
closure is claimed. The complete mandatory gate must run on the final revision.
