# Required prompt forecasting from the original owned K/V audit

This implements the pre-output timing part of FA-111 (§12.7) for the original
learned-code forecast lane. It composes the existing owned source (§10), one-shot
likelihood process (§13), and durable generation/recovery contracts (§16). It
adds no predictor, numerical executor, probability calibration, effect ledger,
source importer, or authority key.

## Explicit configuration, original timing law

After constructing a `FileLearnedConsistencyConfig`, select
`with_owned_generation()?.with_pre_output_forecast()?`. Version three changes
only the configuration domain; all predictor coefficients, event categories,
source bindings, and numerical/storage ceilings remain byte-identical to the
corresponding version-two configuration. Versions one and two retain their
original behavior and encoding. Supplied captures cannot select this timing
contract; a raw residual predictor is not relabelled as a learned-code predictor.

Enable requires the actual original text generator, its matching stream-message
profile when applicable, and the existing model/layer/K-or-V/stream binding before
any numerical work. The original machine retains the immutable learned config
outside numerical checkpoints. Recovery compares that complete intended config;
opening under version two cannot silently remove a version-three requirement.

The SAME existing pre-output guard now handles raw residuals and owned learned
codes. A keyed owned forecast is allowed at the fully accepted prompt boundary,
with no current or lifetime sampling attempts. It uses the existing latest quiet,
source-checked K/V audit and original budgeted predictor. Every other forecast
route, including an unkeyed owned forecast, is rejected in this selected mode.
No new local handle or caller convention is needed to enforce it.

Prompt processing remains possible without a forecast. Both original numerical
intent admission and completion require its current request, source sequence,
actor revision, authority epoch, unexpired deadline and intact likelihood
coverage before sampling. Cached and cooperative callers use these same checks;
semantic journal replay enforces them too. Expiry or lost coverage after Begin
keeps the original intent pending and prevents a sampled completion. Nothing is
refunded and no old quiet state, resampled forecast, or exact fallback is installed.

Only the bound external request can answer the forecast, using the original
complete generated bytes. Early, substituted, unrelated and unkeyed proposals
cannot consume it. A valid observed category is counted once even when later
policy refuses admission; an exact request retry cannot add another observation.
For streams, Message uses the prompt forecast. A later Finish forecast requires
the original receipt-confirmed append and a fresh source sequence, then separate
review and both keys. Dispatch or visible-but-unreconciled output is not confirmation.

## Evidence and limits

Eight authored regression functions use the existing tokenizer, original learned
model/fitter/source checker, file owner and native replay. They cover exact
configuration framing, ordinary/cooperative bypass attempts, pre/post-prompt
routing, complete output identity and retries, legacy-history relabelling,
expiry/lost coverage between writes, atomic bootstrap, numerical budget refusal,
recovery downgrade, and all five Store barriers at forecast/intent/completion.
A paired optional configuration executes identical original generation and
forecast witnesses; only its declared requirement bytes differ. These are source
regressions, not executed results or detector-quality evidence.

The authoring environment cannot launch required RCH validation: `rch` is absent
(exit 127). Rust compilation, tests, rustfmt and Clippy remain unexecuted. Source
hash and selected-context patch checks do not establish runtime correctness. No
bead or qualification gate is closed.

This opt-in contract applies to durable `FileOversight` generation. In-memory
broker users and legacy configurations keep their existing pre-action contract.
Recovery still repeats physical numerical work and requires independently retained
generator/forecast configurations; it is not the full guard-inventory recovery
API. No source authentication, forecast calibration, speedup or general detection
guarantee is claimed.
