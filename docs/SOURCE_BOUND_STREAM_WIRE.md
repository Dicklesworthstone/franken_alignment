# Registered evidence at the stream-intent ingress boundary

`exchange_stream_actor_from_file`, `feed_stream_actor_from_file` and Linux `drive_stream_peer_from_file` connect `FileStreamActorPort` to the original source-aware supervisor and `FileSupervisedDriver`. They reuse the existing private owner-identity check and intake helper; no new evidence provider, request book, policy evaluator, approval path or socket engine is introduced. The two helpers are visible only inside the persistent-host implementation, never through an actor interface.

The complete binary stream intent is checked after the original JSON/frame and ticket-capacity checks, but BEFORE any source or clock access. Invalid stream identity/limits, malformed UTF-8/length/kind, actor-supplied release frames and invalid transport units cannot consume a source read. A foreign wire, channel or peer session is refused before any operation. New well-shaped requests use the original registered-source capture and post-read freshness check, then the original stream builder and request admission. Successful intake is not reported as successful submission: those are distinct journal transitions and separate result fields.

Poll, cancellation, exact retries and conflicting retries need no source read or new clock observation. Fragments and pending response writes/flushes also cannot acquire the next snapshot. A single peer drive retains source-intake diagnostics only for new requests in completed-frame order. The actor receives the original bounded, redacted response rather than private filenames, policy data, helper contexts or native source failures. Linux peer admission still uses the original kernel-credential check; no in-band claim replaces it.

The new methods on `FileSupervisedDriver` retain its existing helper-reaping behavior. They do not grant human approval or drive a congress themselves. Continue through the original source-aware review, human approval, dispatch and publication methods. Raw direct exchange remains usable with a supervisor-prepared one-use snapshot; it does not manufacture one. Reference publication still means the canonical local file, not delivery to a remote audience.

Four new regression functions cover source-prepared two-message/explicit-finish execution through the original full-input congress and separate human key; poll/cancel staying outcome-unknown between publication and reconciliation; read-free retries after the source file disappears; foreign gateways, intent byte limits, malformed intents, fragments and write/flush backpressure; a paired healthy/missing source case after an earlier dispatch that changes publication versus sealing while retaining charges until native reconciliation; and actual Linux peer credentials, fragmented socket input, lost-reply reconnection and read-free retries. Their source-read counts come from the concrete file reader. Existing newly added RefMut-backed tests now compute revision values before mutable receiver calls without changing their assertions. These are test sources, not executed results.

The targeted tests and full `xtask` gate were attempted through RCH; both exited 127 before compilation because `rch` is absent. Rust compilation, rustfmt, Clippy, unit/integration tests and doctests remain unverified. No dependencies, prior domain journal encodings, wire verbs or existing assertion semantics changed. No Beads or production qualification gate is closed. File integrity, clock provenance, actual process isolation and declared observation completeness remain operator assumptions. Transport drive budgets bound socket work, not synchronous source reads, journal replay or storage latency; this does not add a second executor or watchdog.
