# Numerical decoder checkpoint continuation

## Connected consumer

`DecoderSession::checkpoint`, `DecoderModel::restore_checkpoint`, `DecoderModel::recompute_checkpoint` and `DecoderSession::advance_greedy` extend the original-token engine documented in TOKEN_DECODER_REFERENCE.md. The consumer is an L7 numerical continuation experiment: retain the engine's actual completed state, restore its whole cache through the existing writer, then compute subsequent original token IDs with the same forward implementation. This is scoped FA-025/FA-026/FA-027 reference progress, not a qualified native serving checkpoint, production ActorState installation or authority recovery.

The checkpoint inventory is complete for this explicitly restricted engine: the exact immutable parameter object and profile, original token IDs, full registered K/V prefix, source stream, next-token logits and the position derived from token count. Its only selector is deterministic greedy argmax with lowest-ID tie breaking, so this profile has no stochastic sampler or RNG state to omit. Full-prefix causal masking is fixed in the profile. There is no partial token, pending asynchronous kernel, multimodal input, external environment, adapter or serving scheduler in this engine. Other architectures and sampling modes are unsupported rather than silently assigned default state.

## Immutable pinning and identity

Only an actual DecoderSession can construct DecoderCheckpoint. An arbitrary ModelKvImage, edited experiment image or similarly shaped external cache cannot be promoted into it. Checkpoints retain the same immutable model allocation; matching numerical model IDs or constructing a second object with identical parameter bytes is insufficient for restore/recomputation. Cloning the admitted model shares the original parameter object and remains valid. This is process-local identity, not a cryptographic parameter commitment or authenticated model file.

Checkpoint creation copies bounded original-token and snapshot metadata while sharing the existing immutable arrays and logits. Subsequent checkpoint clones share those retained values. The original model/session/capture owners may be dropped without destroying the checkpoint's closure. There are no permits, production resource pools, effect results, policy floors, human keys or live controller handles to duplicate.

Every restored or recomputed session must use a positive stream ID different from the checkpoint's stream. The caller remains responsible for allocating distinct identities across independent sibling calls; there is no global ID registry. A restore receipt retains the original source descriptor and identifies the new capture. Numerical equality is not historical identity: a restored prefix enters the original capture machinery in one bulk append, so its source revision is one even when its original per-token capture had revision N. Subsequent decode uses the actual new frontier. No historical host-buffer receipt is manufactured.

## Restore, recapture and continue

Restoration checks its aggregate cache-value budget and source invariants before allocating the derived destination buffers. It creates distinct CPU-RAM K/V buffers for every registered layer, prepares the entire prefix through ModelKvImage::prepare_restore, and commits the existing lossless writer only after every layer has passed. It then recaptures those written bytes through the original ModelKvCapture all-layer append. Subsequent tokens run the original RMSNorm/RoPE/GQA/SwiGLU decoder, reading that recaptured cache rather than recomputing or substituting it.

Any failed restore returns no partially usable session and cannot mutate the checkpoint or another session. These are private owned buffers and safe-Rust call-level transitions, not a crash-atomic device installation. Empty checkpoints honestly have no logits and no prediction. A checkpoint at its full context remains full after restoration; it cannot gain additional context capacity by being restarted.

A separately callable recomputation path discards the stored cache, executes the ORIGINAL token IDs from the empty state, and compares every layer's retained scalar bits plus the complete next-token logit vector. Stream and capture-revision differences are provenance and are not falsely treated as numeric differences. A value mismatch refuses. Both paths use the same admitted immutable parameters and explicit numerical profile; comparison within this reference engine is not independent evidence of a third-party host's correctness.

`advance_greedy` chooses from the last complete logit vector, then calls the original checked single-token advance. A stale position, budget refusal or late numerical overflow cannot publish a selected-but-half-executed token. There is no hidden generation loop, EOS convention, stop-string interpretation or live effect dispatch. The host explicitly bounds how many subsequent tokens it asks to compute.

## Costs and limits

Restoring a mutable session is not O(1): it writes and recaptures the retained prefix once. The source snapshot arrays remain shared, but the resumed mutable capture has independent arrays. The receipt counts normalized cache values, bytes successfully written, bytes successfully recaptured and the existing writer's offset/scalar staging metric. These exclude allocator overhead, vector capacity, immutable source arrays, temporary buffers and peak process memory. The entire context must already fit the decoder and original per-layer/aggregate KV bounds. The restore-value budget may not exceed the original 16,777,216-value aggregate ceiling.

Restoration does not pretend to have re-executed historical inference. Its new session's successful inference-work counter starts at zero; the source cut and explicit restore work remain in the receipt. Recomputed sessions instead report the actual prefix inference work through the existing DecoderWork model. These are observation/computation counters, never production effect rights or a claim of a globally conserved inference quota. Work after restore still requires explicit per-call product admission. Failed computations may consume unreported work; no throughput, cancellation or peak-memory guarantee is inferred from the numerical limits.

## Regression source and qualification boundary

This increment adds ten public test functions and a compile-fail checkpoint-to-ActorState example. The central test starts from nonzero two-layer grouped-query weights, then compares an uninterrupted session, a buffer-restored session and an original-token-recomputed session for 32 free-running greedy steps. Every step compares the selected original token, all output logit bits and every retained K/V scalar. Another test teacher-forces a differing suffix and compares against fresh full-prefix recomputation at each position. Branch tests verify distinct continuations without changing the parent or sibling.

Other cases cover shared model identity versus separately reconstructed same-named weights, dropping all original owners, restore-budget exhaustion, forbidden source-stream reuse, empty/full checkpoints, atomic greedy refusal, and the distinction between original and derived capture revisions. A literal nonzero logit vector was computed separately with binary32-rounded scalar arithmetic and is compared within an explicit absolute 2e-6 tolerance, not a vendor-kernel bit-identity claim. The initial decoder increment separately includes a layer-major full-sequence oracle rather than deriving all expected values from incremental execution.

There are 22 new Rust test functions and two compile-fail examples across the decoder and continuation increments. They are UNEXECUTED source: this session has no Cargo/rustc or configured RCH runner. Rust compilation, rustfmt, Clippy and the complete revision-bound project gate remain pending. No production or Beads gate is closed, and historical execution receipts do not qualify this source. Real trained-weight ingestion, model-specific tokenizer/architecture negotiation, native runtime admission, GPU synchronization and long-horizon serving-host fidelity remain outstanding.
