# Revalidate the original judgment before first durable publication

Consumer: FileOversight's coupled operator-file endpoint. Plan section 8 and
FA-062 require changes between review and publication to invalidate permission,
not rebase an opaque judgment. This extends the original two-key owner without
another authority, effect sink, policy evaluator or resource-outcome reducer.

## Durable opt-in, no fallback

Call enable_publication_guard before any operator or actor proposal, including
retained refused submissions. Its irreversible mode is an original journal event,
not an actor flag. Once enabled, plain publish refuses. Reopening preserves the
mode. Existing unconfigured profiles retain their explicitly weaker original
publication behavior; they are not described as guarded by this increment.

publish_checked takes the original attempt, an independently supplied whole
CommitteeInput, a policy Snapshot, and the host's explicit elapsed tick sampled
AFTER capture. Before first execution it reuses the original full-input approval
checks, current captured-state gate when configured, policy evaluator, derived
witnesses, authority epoch/ceiling, and the consumed human request's original
control sequence, input revision, action and policy generation. No current value
is written into the frozen review or old permit. The original recheck body is
unchanged and no second authorization operation runs.

Unrelated policy-state changes can retain the same original witnesses. Changed
positive values, absent-key/range membership, semantic epoch, full helper input,
source availability or reviewed control sequence cannot. A rejected basis seals
the original endpoint request before returning Rejected, rather than leaving an
error that can later be retried into publication with better evidence.

The first-execution deadline remains the ORIGINAL endpoint's deadline/second-key
intersection. Expiration uses its existing DeadlineElapsed receipt. Resource
version conflicts remain the endpoint's own compare-and-publish result. Already
retained terminal outcomes take precedence over later source loss or expiry;
retention loss does not produce a fabricated outcome.

## Publication is not acknowledgment

Checking, execution or sealing occurs in the existing private RAM replay candidate.
Only successful canonical-file replacement exposes its CheckedPublication result.
A storage failure returns no candidate outcome or refund and faults the old owner.
The original charge and actor Unknown disposition remain until the existing
reconciler accepts the endpoint's actual terminal evidence. A sealed attempt can
never be revived by calling publish_checked with restored inputs.

After reopening, missing requests have no reconstructed sendable envelope. This
API cannot bypass the original recovery fence. They remain query/seal-only;
retained execution evidence still settles without helpers or a human key.
New tags 13 and 14 extend only the oversight journal. Existing bootstrap and event
bytes are preserved; old readers reject those tags, not silently downgrade them.

## Verification and limits

Nine public regression functions cover quiet publication, post-dispatch changes
in six evidence dimensions, unrelated state versus absent/range witnesses, changed
control context with a fresh successful action, original expiry, historical
execution after source loss/reopen, mode installation and legacy controls, clock
refusal and envelope nonresurrection, and real staging-write failure for both
successful and rejected validation candidates. One compile-fail example separates
a checked observation from an effect permit. Existing assertions are unchanged.

Rust compilation, formatting, Clippy and execution have not run in this editing
environment; RCH is unavailable. Source/diff checks are not a passing gate and no
bead or production qualification is closed. Synthetic ballots are not evidence
of detector quality. No dependency, alternate executor or global status changed.

The supplied snapshot, helper input and clock are trusted observations. This is a
logical coupled transaction, not authentication, a physical-time latency bound,
or a lock over arbitrary external-world changes during filesystem work. Host
adapters must bind and serialize their real observations at the actual effect
boundary. Malicious file rollback, hostile-process containment and durable hosted
decoder migration remain outside this operator-controlled reference profile.
