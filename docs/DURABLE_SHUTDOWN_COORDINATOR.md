# Durable write-ahead shutdown coordination

`FileShutdownCoordinator` consumes the original fixed-roster `FileShutdownPlan` and drives its original campaign. Its separate operation store uses the existing exclusive owner lock, bounded reader and write/file-sync/rename/directory-sync replacement protocol. The store tracks visits and byte-exact observed history heads, not action authority, balances, credentials, votes or a second endpoint. Every effect transition remains an original `FileOversight::request_stop` or `progress_stop` call.

Each visit first appends and acknowledges an `Entered` intent. Only then may the coordinator borrow an actor supervisor, inspect a domain or invoke native stop/drain. Completing a visit records its observed domain revision or exact error-display diagnostic and any newer whole-history head in a second replacement. An outer error means coordinator completion was not acknowledged; an inner error means the original domain refused and that refusal was acknowledged. A failed intent cannot touch the domain. If the domain commits but completion fails, the last acknowledged coordinator image retains an entered, unresolved visit. The original canonical-inspection path resolves that ambiguity without repeating a stop or inferring nonexecution.

The coordinator poisons itself before encoding or persistence and stays unavailable across native work until completion acknowledges. Caught unwinds cannot make its old report reusable. Reports retain the last acknowledged coordinator cut and expose unavailability separately. Operator-supplied unavailable observations can only withdraw success. Actual effect outcomes and charges remain in the existing domain journal; their original stop sweep is returned by a fresh campaign observation, never synthesized from visit metadata.

Reopening requires the exact plan image, byte capacity, canonical coordinator path and an independently supplied minimum revision. All decoding, plan comparison, bounded head parsing and anchor-prefix checks precede staging cleanup. The original visit allowance spans every restart and includes unresolved/failed visits. The updated head for every member survives, so a later domain rollback below an already observed prefix is still rejected. All roster members remain present. Reopening itself needs no reachable domain and performs no numerical execution or native recovery. Saved observations are deliberately not restored as current success; the report separates historical `visits` from a newly unobserved `current_session`.

The plan can be rebuilt after whole-process loss using `FileShutdownPlan::decode` and independently supplied member configurations. An expected revision floor detects older coordinator images, not equal-counter coordinator forks; archive/manifest integrity remains operator-controlled. This does not authenticate a remote host, establish a simultaneous fleet snapshot, implement lease expiry or run a watchdog while unscheduled. A malicious operator can create a different store or unmanaged campaign. Limits are cooperative visit counts and serialized bytes, not OS isolation, RSS, numerical-replay or wall-clock budgets. The coordinator's image uses the existing Store ceiling of 16 MiB; plans and retained heads that do not fit are refused. A final-image capacity failure leaves the already acknowledged intent unresolved, never returns speculative completion and never refunds a native effect.

Four public integration regressions cover two real domain files with executed/unresolved/undispatched effects across complete coordinator reconstruction; retained visit exhaustion and domain rollback across repeated reopen; pre-intent storage failure and exact-plan/floor validation before cleanup; and the original restricted actor gateway staying outcome-unknown until native reconciliation. Four unit functions add ten actual Store failure barriers across intent and completion, a caught interruption after a real domain stop, every wire truncation plus invalid revision/suffix controls, and exact completion-byte exhaustion contrasted with a sufficient-capacity drain. The positive controls reach original native drains. One compile-fail doctest rejects coordinator cloning. These tests are source additions, not reported passing execution.

RCH was attempted but is unavailable (exit 127 before compilation). Compilation, rustfmt, Clippy, tests and doctests remain unverified. No dependencies, prior domain journal encodings, original assertions, Beads statuses or production qualification gates are changed. The new coordinator bookkeeping format is not a new action-authority algorithm.
