# Provision mandatory policy campaigns in a learned history

The single learned publication command can install original policy-campaign
governance in the first acknowledged image, before numerical work, proposals or
effects. This connects the existing native governance guard to operator creation:

```text
supervise_publication create-learned-generated CONFIG LEARNED_RECIPE REVIEWER_PROFILE \
  --campaign-profile CAMPAIGN_PROFILE \
  --retain-history-anchor NEW_OUTPUT_ANCHOR
```

The profile is a closed `fa.policy-campaign-profile/1` document with independently
selected nonzero native limits:

```json
{
  "schema": "fa.policy-campaign-profile/1",
  "cases": 16,
  "input_bytes": 1048576,
  "max_campaigns": 8
}
```

All three quantities are JSON unsigned integers and must fit their existing
native maxima. Unknown or duplicate fields, strings in numeric fields, zero
limits, missing operands and repeated selection refuse. The profile must be
retained outside the authority store. Its presence explicitly authorizes this
first-image guard; a recovery-policy description alone cannot install it.

The original guarded constructor composes campaigns with the numerical recipe,
stream, mandatory policy source, terminal reserve, any registered identity and
credential guards, and either original predictor mode. It returns the existing
human and observer roles through their existing custody paths. The creation
flag grants no governor, reusable campaign approval or effect permit. Ungoverned
policy replacement refuses once the campaign guard is installed.

Creation with the flag still performs actual model generation, native sidecar
commit/reveal, independent human approval and original publication. The flag
can accompany the single live actor/precheck service and an eligible explicit
live checkpoint. It is refused on continuation, Finish, resume and historical
maintenance; it cannot add a guard to a history after work has begun.

Recovery must independently select the exact installed campaign inventory in
the existing `fa.learned-recovery-policy/2` envelope, plus the current effective
policy and retained history anchor. The creation flag is not a substitute for
those recovery expectations. Missing or changed campaign requirements refuse
before acknowledging a recovery fence.

The separate [explicit policy-governance command](LEARNED_POLICY_GOVERNANCE.md)
can promote a reviewed candidate in an eligible campaign-protected history.
It requires the full original report and independently selected governor
intent; the creation profile does not itself approve any policy change.

Five regression functions cover full command parsing and real native/human
publication, guarded native policy refusal, plain/raw/owned first-image custody,
exact anchored recovery, malformed profiles and incompatible modes. These are
authored source with source/syntax review; RCH compilation and runtime execution
remain pending. They provide no production calibration or packet closure.
