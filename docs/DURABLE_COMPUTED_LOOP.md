# One host loop for computed congress and durable publication

Status: unqualified source integration for FA-113 and the existing FA-014 recovery
boundary. This extends the explicit [learned driver](DURABLE_LEARNED_DRIVER.md)
without changing its evaluator, original journal format, source contracts or
mandatory effect keys. It serves the existing plan sections 9, 10.15, 16 and 17;
no founding semantics or dependency admission changes.

## Opt in once, then drive the same request

After `start_learned_probe_review`, a host may use
`FileSupervisedDriver::step_with_computed_evidence` for the entire request rather
than dispatching between a manual numerical loop and the ordinary effect loop.
`step_with_computed_evidence_and_credential` supplies the same separate credential
capability used by the original publication path.

During a running learned review, the combined loop takes a current provider
observation through the original sampling and validation path. The complete
input must equal the original current job input. A copied old coarse packet
cannot authorize scoring after refinement. Changed or missing input withdraws
the original captured basis; provider/source/clock errors close this local job
and the original maintenance path cancels computation without discarding work.

Only `advance_learned_probe_review` advances the privately retained original
numerical owner, including its source/revision checks, complete roster,
commit/reveal, residual refinement, accounting and durable finish. A running
pass returns the existing Workers event with actual coordinator statuses and
an empty I/O map: no socket work took place. Refined input and the next review
remain owned by that original driver. Continue is not manufactured by the loop.

After the original applied result, this method delegates to the unchanged
ordinary state machine. Human approval, automatic reservation, dispatch,
source-checked and optional credentialed publication, and reconciliation all
use the existing implementation. Unknown dispatches remain query-only and do
not acquire fresh evidence, repeat helpers, resend an effect or refund a charge.

The original `step_with_evidence` still refuses a running computed review before
calling its clock or provider. Existing socket/process callers do not silently
opt into a different behavior. The new loop neither substitutes a socket review
nor invokes another finish operation, and no prior refusal test is relaxed.

## Custody and nonclaims

The existing RetainedReview stays in the driver until explicit extraction or
release, including across failed provider acquisition or a poisoned store. No
new evaluator, evidence importer, event tag, reviewer role or effect ledger is
created. Historical diagnostics are not independently current observations.
A recovered owner still pauses original inference and withdraws old authority;
this loop cannot recover a lost process-local numerical evaluator.

Each native poll keeps its original bounded numerical/protocol quantum. Source
capture, an individual computation and journal replay/I/O remain synchronous.
Trusted provider and elapsed-clock assumptions remain unchanged. No wall-clock
latency, process independence, trained-detector quality, hardware durability or
production qualification is claimed.
