# Restore the complete shutdown roster after process loss

`FileShutdownPlan::encode` retains the original operation, exact sorted domain roster, attempt/head limits, canonical directories and entire registration-history anchors. `FileShutdownPlan::decode` requires an explicit independently supplied `FileShutdownMember` for every domain. The existing journal decoder validates each anchor against its original bootstrap, directory and event count. Missing, duplicate, renamed or differently configured members cannot be silently substituted. Aggregate anchor bytes, paths, record counts and trailing data are bounded.

The decoder performs no domain filesystem reads or numerical execution. It therefore restores the roster while domains are unavailable, without opening owners, cleaning staging files, refreshing clocks or issuing roles. The existing campaign consumes the reconstructed plan and still compares exact history prefixes against the actual owner or canonical image before reporting progress. Starting a decoded plan does not restore old stop acknowledgments or success. Every member begins unobserved, including one whose older campaign had already reported a drain.

Archive origin and integrity remain operator responsibilities: this is a deterministic bounded configuration format, not a signed receipt or an independent authenticity check. The manifest binds bootstraps and paths; it does not make arbitrary replacement archive bytes authentic. Serialized registration anchors cannot grant action authority. A new campaign retains the previously documented per-instance attempt budget; durable coordinator visit accounting is separate.

Four integration regressions cover an offline member across plan restoration and original owner recovery, complete two-domain stopping/draining, independently assembled wire bytes and every truncation, changed bootstrap and roster refusals, nonrestoration of old aggregate success, invalid canonical evidence, original attempt limits and preservation of staging files. These are added test sources, not executed results. The artifact's consumer is the existing multi-domain shutdown campaign; the format prevents loss of its configured denominator at process boundaries.

RCH is unavailable in the implementation environment. Rust compilation, formatting, Clippy and test execution are unverified. No dependencies, original authority/journal encodings, old assertions, Beads state or production qualification gates change. This does not establish authentication, distributed ordering, watchdog execution or hardware power-loss durability.
