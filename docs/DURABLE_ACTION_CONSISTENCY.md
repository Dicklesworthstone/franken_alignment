# Durable pre-action prediction and action consistency

`FileOversight::enable_action_consistency` installs the ORIGINAL activation-conditioned predictor and exact lifetime likelihood process before any proposal or external actor request. The bounded configuration retains exact binary32 probe coefficients, capture identity, forecast table, event-prefix definition, policy generation, lifetime alpha, stream, prediction cap and age limit. Constructors reuse the original probe, forecast and evidence types. Registration is supplied calibration, not calibrated by being serialized.

A separately held `FileConsistencyObserver` supplies captured frames, never probabilities or a claimed match. `forecast_action` returns only after the canonical record acknowledges. At most one native forecast is outstanding, bound to its attempt, actor revision, authority epoch, source sequence and time window. A missing capture can be reported through `unavailable`, including while another evidence source is interrupted or numerical execution is paused. This records the original permanent coverage-loss latch; it cannot clear either independent gate.

The original broker observes an admissible action category before downstream policy and resource admission. In this configured profile, ordinary `propose` now commits a native refusal together with its evidence mutation before returning `JournalError::Contract`. `propose_consistent` makes the distinction explicit: an inner refusal is acknowledged history, whereas an outer error is not an acknowledged transition. The original external-key `submit_request` retains both its proposal refusal and this same evidence mutation. Exact external-key retries do not create another observation. Existing unconfigured proposal behavior and event encodings are unchanged.

Entering a new prediction or proposal observation poisons the live owner before the operation; a caught unwind or persistence failure cannot expose the older permitting evidence as a reusable owner. The canonical replacement clears that latch only on acknowledgment. Context-valid prediction-capacity failures retain coverage loss even though the native call returns an error. Historical inspection is not a current permission.

Quiet prediction is not approval. The original congress, whole-input identity, human key and first-publication checks still apply. A threshold crossing, coverage loss or unresolved pending forecast prevents permitting review/authorization/publication through the original consistency predicate. Reconciliation remains independent: an uncertain dispatch retains its charge until the original endpoint result resolves it. This integration does not turn a likelihood crossing into an automatic run-stop policy.

Recovery reconstructs the same exact integer likelihood product, sequence floor, prediction count and observations. If a forecast was still pending, its outcome is censored: the original pending record stays visible and recovery permanently marks coverage lost. It never silently skips the forecast, resets alpha or calls that incomplete prefix a fresh quiet run. A fully observed quiet history retains its lifetime evidence; future predictions require a fresh clock and the same registered policy generation. Generic recovery does not reissue the old observer role. A new profile or re-arming policy is not supplied by this change.

Journal family 28 contains only exact configuration, full-precision frame inputs and explicit unavailability. It does not load a stored likelihood, calibrated score, helper vote, verdict or permit. The original numerical predictor and broker recompute them during semantic replay. The canonical file, source origin, clocks and declared calibration remain trusted reference-profile inputs, not authenticated evidence.

Eight public regression functions cover permitted prediction-to-two-key execution, refused/denied proposals counted before admission, a latched crossing despite unanimous helper votes, pending-forecast invalidation after dispatch, preserved recovery/censoring, expiry/capacity refusal and foreign-role/predecessor controls, and reusable clock/request preflight refusals. Four unit functions cover an independent configuration vector and all truncations, source-interruption preservation, and ten original Store barrier scenarios across prediction and refused-proposal publication. Two compile-fail doctests separate snapshots from permits and prohibit observer cloning. These are added tests, not reported passing executions.

The required RCH invocation exited 127 because `rch` is unavailable, before compilation. Rust compilation, rustfmt, Clippy, tests and doctests remain unverified. No dependency, original assertion, Beads closure or production qualification is changed. This serves the pre-action prediction/latent-output consistency path in plan section 12.7; it establishes neither real-world conditional calibration nor detection of deceptive intent.
