# Numerical work without an acknowledged journal result

The durable decoder now retires the live owner immediately before entering a new numerical operation, not only before the filesystem replacement. A completed token can be held or failed, and forming its comparison witness or encoding the expanded journal can still fail. Previously those errors discarded the candidate while leaving the older quiet prefix usable. They now retain the existing unavailable latch. No new token, permitting result or automatic retry is returned; the last acknowledged inspection remains historical data.

Unconfigured, unclocked, recovery-paused, stale-journal and exhausted-event preflights remain before this boundary. Normal committed native refusals retain their original result and clear the latch only when the same canonical replacement acknowledges. The existing source interruption check, decoder evaluator, effect accounting and journal encoding are unchanged.

Two public regression functions pair successful quiet/held sampling with a store whose exact byte budget admits the preceding prefix and recovery fence but not the next token witness. The tests check blocked subsequent proposals and inference, unchanged canonical bytes, no pending write, and explicitly paused recovery. A separate permitted control checks that pre-computation refusals do not poison a usable owner. No new fault seam or replacement numerical evaluator is introduced.

Rust compilation and tests remain pending. The required RCH invocation was attempted in this environment but rch is unavailable. Source and Git checks do not establish a passing Rust gate, production durability or hardware power-loss behavior. No Beads or qualification claims are promoted.
