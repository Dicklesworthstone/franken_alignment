# Capability-free investigation of durable decoder checkpoints

`FileOversight::investigate_decoder_checkpoint` starts a fixed paired numerical experiment from the ORIGINAL checkpoint captured by that owner. The private bridge reads only the numerical half of the original native pair. It does not reset the actor, use today's later continuation as the checkpoint, import a caller-provided model/cache, retain the saved sampler, copy effect rights or recover approval keys. The source handle must match the current file owner, including after recovery. The API remains on the trusted supervisor owner, not the actor port.

`FileInvestigationRequest` fixes the experiment ID, exact KV edit preimages/scopes, edit limit, forced or greedy continuation, complete horizon and combined product/logit budget. The original sparse-intervention validator and numerical engine admit them; unvalidated edit maps are moved rather than copied before their bounds are checked. `FileDecoderInvestigation` then uses the existing cooperative paired cursor. Every advance computes at most one complete arm-token; cancellation, failure, partial-pair accounting and full-horizon completion retain that cursor's semantics. The original eager comparison remains the independent execution-loop oracle.

Origin evidence retains the canonical directory identity, selected journal revision, source scope, original checkpoint metadata and exact immutable decoder configuration (including actual parameter input bytes). The completed report binds those to the original request and original numerical comparison. Purpose is explicitly Experiment. The returned object has no live broker, role, mutable decoder, saved sampler or publication endpoint; it can outlive its source owner. A successful or quiet experiment cannot clear a live hold, undo a terminal stop, reset the incident counter, refund a pending effect or authorize a publication. Existing two-key approvals are neither restored nor invalidated by passive investigation.

`FileOversight::read_decoder_investigation` also prepares the experiment directly from a canonical file beside a locked or faulted owner. It pins the exact expected numerical configuration before executing historical tokens and validates the entire original history, including suffixes after the selected checkpoint. It acquires no writer lock, cleans no staged file, observes no clock, appends no recovery fence and returns no role. It can investigate the canonical image while the live owner's last acknowledgment is unavailable. This reads one historical image, not an independently authenticated or rollback-resistant head. Missing checkpoint means absent from the selected image, not proof that no operation happened.

An acknowledged held, stopped or recovery-paused owner remains investigable without fresh permitting observations. Normal computation and effects still require their unchanged gates. Failed or cancelled experiments retain separate entered/completed work without charging the live effect ledger or changing the actor's lifetime monitoring counters. Budgets cover the paired continuation only: whole-history reconstruction for the read-only entry point is additional work, and this API supplies no fleet-wide investigation ledger, preemptive cancellation, latency/RSS bound, OS sandbox or automatic experiment-to-policy promotion.

Seven public regressions cover real KV edits that change subsequent choices, branching from an earlier checkpoint while preserving later state and valid two-key publication, held/terminal-stop preservation despite a no-op counterfactual, failed/cancelled branch accounting without poisoning the actor, foreign and pre-recovery handles, passive paused recovery, read-only inspection beside locked/faulted owners and staged files, exact configuration, a corrupted post-checkpoint numerical suffix, and edit/horizon refusals with permitted controls. Two compile-fail doctests prevent report-to-permit conversion and cursor cloning. These are added source tests, not passing execution results.

This serves the capability-free branching and paired-diagnosis obligations in plan sections 11.3 and 12.1 using existing reference semantics. Tiny numerical fixtures establish neither causal necessity nor calibrated detection of malicious intent. Model, path, clock and observation trust roots remain independently provisioned. The RCH verification command was attempted and exited 127 because `rch` is absent; Rust compilation, rustfmt, Clippy, tests and doctests remain unexecuted. No dependencies, journal encodings, original assertions, Beads status or production qualification claims were changed.
