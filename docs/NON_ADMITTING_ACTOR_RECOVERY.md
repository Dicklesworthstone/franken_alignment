# Recover existing actor tickets without admitting replacement actions

`FileActorPort::recovery_only()` produces `FileActorRecoveryPort`, usable by the original ActorWire, ActorChannel, UnixActorConnection and Linux PeerSession. It accepts the original Submit representation only for a request already retained by the same original FileDelivery or FileOversight owner. The ordinary gateway compares every original proposal field before returning a ticket. Missing records are Withheld, not a fictional NotAdmitted or Absent outcome. No source, clock, snapshot, allocator, new journal encoding, or alternate outcome reducer is added.

The wrapper first reads the actual sealed host's request book. These owners never delete or reassign a retained key, and the same non-Send gateway retains that owner while the original retry runs. There is no external callback or scheduling point between checks. A new key cannot consume a preinstalled one-use snapshot. A retained downstream refusal is recoverable even without a frozen admitted action. Faulted owners refuse rather than return their older acknowledged state.

`for_request` further narrows the capability to one independently selected key across Submit, Poll and Cancel. It cannot widen or switch to another key, and there is no admitting-port unwrap. Existing ordinary ports independently held by the supervisor are not revoked. The wrapper keeps weak custody: it cannot keep the authority lock alive when its supervisor is dropped. A ticket from another gateway is still withheld by the original issuer check.

This is non-admitting, not fully read-only: Cancel still invokes the original cancellation rule. Only an undispatched reservation can be released; sent and executed liabilities remain charged, and endpoint outcome stays Unknown until reconciliation. Connection authentication and exact server/domain provisioning are still required. Numeric IDs alone cannot recover tickets, and peer credentials do not attest the server's executable or persistent storage. The wire format is unchanged: a receiver is independently configured in this restricted mode; an arbitrary admitting server does not acquire it because a client intends recovery.

The runnable receipt-only service is the next consumer. This supports safe exact resubmission of an unanswered original request to that explicitly restricted receiver without creating a new action if no server record exists. It does not weaken the existing durable cancellation command's requirement for a recorded acknowledgment when connecting to an ordinary admitting service.

Six regression functions cover missing keys with a preserved snapshot and admitting positive control; every changed proposal field, per-key narrowing and foreign tickets; original cancellation before/after dispatch and execution; retained admission refusals through FileDelivery; a real Unix lost-reply/executed-request recovery; unavailable and borrowed owners. One compile-fail test rejects conversion back to admitting capability. Tests are authored, not executed. Required RCH verification is unavailable in this editing runtime; compilation, tests, rustfmt and Clippy remain unverified. No old assertions, dependencies, Beads states or qualification gates change. This advances the FA-107/FA-014 reference recovery integration, not full packet closure.
