# Prepaid successor reviews for ordinary learned output

An ordinary one-round learned review can reserve additional native helper
cohorts before its first Begin. If its original Message or Finish receives an
applied Hold, an independent operator may explicitly request a fresh review
from that reserve. The original output, learned sidecar, actor work and human
publication requirement remain unchanged.

This is a separate mode from the existing
[fixed-slot learned continuation](LEARNED_HELD_REVIEW.md). That mode retains
its original progressive schedule, next round ID and fixed review window.
The reserve mode admits exact helper owners and all their cost in advance,
while allowing a fresh round ID and review window to be selected after an
explicit request, within the original action deadline. It does not extend an
existing fixed slot or silently reconfigure a progressive review.

## Reserve the actual helper owners before any verdict

`FileSupervisedDriver::start_native_learned_sequence_with_convening` accepts
the original launch and a finite list of additional native rosters. This
mode requires one initial scheduled round and an ordinary nonpredictive
source-only learned stream. Every reserved evaluator, probe query and salt is
constructed and checked before the first Begin. No post-Hold method accepts
replacement models, helper packets or new resource limits.

The initial review and every reserved cohort share the original total round
bound, native evaluation, scalar-product and sampling reservations, and poll
ceiling. Insufficient explicitly requested reservation fails admission.
Unused work does not refund a reservation. Review records, failed work,
disclosure spending and actor numerical counters remain cumulative.

The original start method continues to select the existing fixed-slot mode.
An independently chosen operator grant supplies a separate finite operation
ceiling; it never creates native work capacity.

## Keep one original live review and one offer

The same `FileNativeSupervisedDriver` stays alive across the Hold. It retains
the original completed sidecar, exact action and source, receipt-confirmed
audience, closed publication job and cumulative native history. Its existing
weak native-offer mechanism describes the reserved mode as well as the fixed
mode; there is no second authority owner or reconstructed handoff.

`has_reserved_successor()` observes whether the original retained reserve can
serve the current Hold. `take_pending_convene()` consumes only an independently
admitted ticket. The reserved path uses
`convene_reserved_from_policy_file(source, ticket, window, clock)` to open one
new round with the next actual prepaid cohort. The original fixed-slot method
and its window remain unchanged.

Next, admission and consumption bind the same current held predecessor,
authority epoch, input revision and live weak custody. Reserved mode requires
an unused round ID; it cannot borrow the fixed mode's exception for its exact
already leased slot. Dropping the original wrapper, taking its terminal
handoff, cancellation, source failure, exhausted native work or recovery
withdraws the offer. A retained transcript cannot recreate it.

## Reacquire evidence before opening the fresh round

The complete ticket, original numerical state, input and confirmed audience
are checked before topology, policy-source or clock work. Topology-selected
owners retain the same source custodian and pay their original fresh review
check. The original policy provider captures complete current evidence for
the exact same learned packet. Changed source binding cannot replace that
packet or turn a different generation into the held request.

The trusted host selects the fresh review window within the unchanged action
deadline. The operator supplies neither a clock nor a claimed verdict. Capture
and Begin recheck the actual time and current predecessor. An admitted failure
retires remaining native custody, keeps its paid work and spends the one-use
operation. Reconnecting, fixing a file or repeating a command cannot refund it
or start an automatic retry.

Only a new original Continue can return the publication job to Ready. Its
effect still needs a fresh independent human key and every original source,
identity, credential, joint-review and final-publication check. Stop and actor
cancellation remain available while the request is held. Process-helper and
predictive learned recipes remain outside both supported native modes.

## Verification boundary

Regression sources use real source-only learned Message/Finish generation,
original native evaluators and the existing independent publication keys.
They exercise successful continuation together with exhausted reservations,
stale or withdrawn input, foreign custody, bad source, invalid windows and
human rejection. Their fixture models test protocol behavior, not detector
accuracy. Source inspection and syntax parsing are separate from required
RCH compilation, runtime execution, Clippy and full qualification.
