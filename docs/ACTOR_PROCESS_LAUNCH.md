# Launch an external actor on the original request protocol

`ActorProgram` and `ActorProcess::launch` connect a real operator-selected executable to an existing `ActorWire` using a private full-duplex inherited stdin socket. The existing actor client attaches with `ActorClientState::connect_process_stdin`. The actor still speaks the original Submit/Poll/Cancel protocol, including the sealed stream-intent port when selected; it receives no supervisor, helper connection, reviewer role, evidence provider or effect key.

Launch reuses the original helper program's bounded path/argument/environment validation, metadata preflight, env_clear and socket/Command setup. Helper launch still validates the complete roster before its first spawn. Both launchers use the same native direct-child polling and termination implementation. No shell, PATH lookup, executor or background reaper is introduced. All explicit program arguments and environment remain operator-controlled and must exclude private credentials. stdout/stderr are private host diagnostics, never accepted protocol frames. A path check is not executable-image attestation, and inherited socket possession is a launch handoff, not SO_PEERCRED executable authentication.

A failed launch returns the original ActorWire session and no child. Protocol buffers and fallible socket setup precede spawn; the child is retained immediately on success. `drive` uses the original bounded nonblocking socket engine. Invalid budgets precede all work. A caught admission unwind latches interruption: another drive cannot replay the partially executed intake and requests termination instead. Clean transport closure retains the process until explicit polling or termination; it never implies an effect result. `request_stop` closes ingress before requesting termination. `poll` performs one try_wait and at most one kill. No blocking wait runs in production or Drop. Callers must retain and poll the owner until the direct child is reaped; Drop makes only bounded best-effort cleanup and reports unreaped children.

After confirmed reaping, `into_session` returns the same original ticket session. A running process returns its entire owner on refusal. No restart or retry is automatic, no lifetime request budget is reset, and no process event cancels an admitted action or settles a dispatched liability. The durable publication owner, original congress, human key and endpoint reconciliation remain authoritative. The process owns only the actor's weak gateway, not the durable authority lock.

Five public regression functions plus a separately re-executed child fixture cover actual process/client submission through congress, human approval, publication and reconciliation; termination while a dispatch remains charged; successful child exit with an action still pending; launch failures retaining tickets and invalid-drive refusal; and pipe-stdin rejection, environment clearing and diagnostic separation. The child fixture is an analytic client, not model inference. One compile-fail doctest rejects actor-process access to the broker. Existing test assertions are unchanged.

RCH is unavailable in the implementation environment. Compilation, rustfmt, Clippy, tests and doctests are not verified. These changes implement an external-process connection, not an OS sandbox, process-tree termination, credential boundary, remote actor identity, deadline watchdog or production qualification. Ambient filesystem/network permissions, descendants, non-CLOEXEC descriptors, program provenance and stderr isolation require a separately qualified host. No new dependency or journal encoding is introduced.
