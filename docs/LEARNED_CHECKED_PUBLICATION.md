# Checked learned publication

Learned generation can require the original final-publication witness gate in
the same immutable configuration as its model, tokenizer, fitted codec, probes,
source policy, forecasts, identity registration and helper qualification. This
composes the existing learned owner with the existing validator; it does not
introduce another validator or another source of effect authority.

## Native registration

`FileLearnedConfig::with_required_publication_validation` accepts a
`FileLearnedPublicationProfile` containing:

- `limits`: the original `PublicationLimits`, including the finite binding and
  validation-work allowances.
- `feed`: optionally, the original `GeneratedPublicationFeed`, containing the
  exact change-feed policy, producer freshness policy and explicit snapshot
  fallback selection.

The existing learned configuration already binds the stream, and the owning
constructor independently selects its recovery reserve. The new profile supplies
no evidence capture, producer heartbeat, helper verdict, human approval or
publication key. `required_publication_validation` returns this registration,
not a live evidence-health assertion.

The disjoint `FALPUB` recipe wrapper retains the complete original configuration
and encodes the selected original witness bootstrap events. Unselected recipes
retain their original bytes. A repeated selection refuses, and the complete
wrapper order remains part of the independently retained recipe identity.

The original learned Enable transition installs the witness, change-feed,
freshness and optional exact-snapshot guards before exposing a numerical owner.
It runs the original validators, including the producer clock-domain check.
Invalid or conflicting registrations refuse before a newly created store can
become visible. The same installation is used by ordinary, raw-predictive,
owned-predictive and topology-mediated learned constructors; identity and joint
credibility remain separate prerequisites.

## What must happen before publication

Each actual attempt must bind its original action and original publication
evidence before helper review. Structured witnesses can depend on exact values,
absent keys, empty ranges and complete range membership. An opaque witness binds
its complete declared input and interpretation epochs. The original producer,
capture and feed APIs retain their existing provenance and completeness rules.

Current evidence is acquired and validated at the original authorization,
dispatch and first-publication boundaries. A changed relevant value, a new
member of a previously empty range, changed opaque input, incomplete change
history or unavailable required evidence cannot be repaired by reusing a human
approval. An unrelated change remains eligible only after the original validator
establishes that the required dependencies still hold.

If a relevant change arrives after dispatch admission, the first-publication
gate uses its original sealing operation. It does not deliver the obsolete
effect, reinterpret the old review, or treat cancellation as proof of a remote
outcome. The original dispatch charge, settlement rules, historical review and
request identity remain authoritative.

## Recovery and historical inspection

Every learned recovery, historical receipt and audit path already compares the
complete independently supplied numerical recipe against the canonical journal.
The new registration therefore participates in those same comparisons. Omitting
or changing its limits, feed, freshness or fallback policy cannot reopen the
same history under a weaker recipe. Mismatch refusal precedes numerical replay,
staging cleanup, the recovery fence and role release.

A matching recovery still pauses the original numerical owner and withdraws
old eligibility through the original fence. It preserves acknowledged tokens,
sampler draws, forecast expenditure, effect liabilities and original receipts.
Fresh evidence and both original effect keys remain necessary for a new
publication. Historical inspection cannot manufacture a new capture or turn an
old receipt into permission to send again.

## Scope

This is a bounded reference integration of FA-062, plan sections 7.6–7.7, 8.7–8.8
and 16.4, and the existing Epistemic MVCC judgment-witness addition serving
FI-A13/FI-A17. It changes no plan meaning, journal tag, authority role, dependency,
revocation rule or license.

The local publication sink and operator-selected evidence sources retain their
existing trust assumptions. This is not authentication of arbitrary filesystem
content, remote delivery, a complete deployment perimeter, calibrated detection
quality or a release qualification. Current execution evidence and remaining
qualification limits are recorded in [implementation status](../IMPLEMENTATION_STATUS.md).
