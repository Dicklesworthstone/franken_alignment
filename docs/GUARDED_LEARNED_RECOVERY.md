# Composed guarded learned-generation lifecycle

This source addition connects the existing L5 guarded bootstrap/recovery paths
with the original learned numerical owner. It serves the effect-boundary and
rewind contracts in plan sections 8, 11.2, 11.10 and 16.4, and founding ideas
FI-A02, FI-A16 and FI-I03. It introduces no replacement inference engine, storage
format, authority reducer, guard policy or production qualification.

`FileOversight::create_guarded_with_learned_generation` prepares the original
guard sequence, resolves any registered credential route through its original
resolver, and applies the original learned Enable event before publishing the
FIRST canonical journal image. The returned human reviewer, identity observer
and policy governor remain separate roles. Creation supplies no current clock,
identity observation, source eligibility, numerical step or effect key.

`open_guarded_with_learned_generation` requires both independently retained
`FileRecoveryRequirements` and a complete `FileLearnedConfig`. It compares the
actual learned recipe before numerical replay, then checks the original guard
inventory, effective policy, credential epoch/revocation and all three recovery
floors. Only successful admission permits cleanup and the original single fence.
Roles are provisioned only after that fence is acknowledged. Missing configured
roles cannot silently become optional. The classical decoder and learned engine
cannot be requested together. Unexpected evaluated, predictive or mediated
extensions are refused by the base profile's existing inventory checks.

The original recovery reducer pauses the learned owner, withdraws old human keys
and identity/campaign eligibility, and preserves dispatched/unknown liabilities.
A fresh clock and explicit original resume are required. A pending numerical
intent remains pending; resume cannot skip it. Held/failed generators remain
nonresumable. Original congress, source, identity and two-key publication checks
still govern new effects. This is the local journal-as-publication profile,
not distributed recovery or an authenticated host/capture protocol.

The recipe can be a numeric or native-text FileLearnedConfig; its original
encoding and output restriction are unchanged. Counter floors reject older cuts,
not equal-counter forks, and all independently supplied requirements must be
retained outside the rollbackable journal. Runtime replay and memory/work costs
are those of the original complete-history implementation, not a cheap checkpoint
installation or an Asupersync runtime admission.

## Authored verification

Nine integration tests use actual original decoder/codec/probe calls and real
local journals. They cover atomic initial bootstrap, every identity/governor
presence combination, fresh usable identity/human roles after recovery, old-key
refusal, exact numerical/spent-budget preservation, pending intents, real monitor
holds and budget failure, unresolved dispatched liabilities, independent recipe/
guard/policy/floor mismatches before cleanup, exact event capacity and exclusive
ownership. Helper ballots and model coefficients are synthetic controls. These
cases do not qualify detector effectiveness, credential isolation or all possible
guard combinations.

Rust compilation, tests, rustfmt, Clippy and the required RCH gate are UNEXECUTED
in this preparation environment. RCH and the Rust tools are absent. Source and
Git integrity checks are not runtime evidence. No Bead or release gate is closed.
