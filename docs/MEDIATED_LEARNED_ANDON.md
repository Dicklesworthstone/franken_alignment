# Learned publication with topology and independent accounting

Learned generation can retain topology enforcement, independent evaluation and
Andon accounting in the same durable owner. This composition keeps the original
numerical recipe, graph checker, evaluator, accounting reducers and canonical
writer. It introduces no journal format, alternate numerical replay or new
publication authority.

The work serves FA-026/073/105 under plan §§9.9, 11.2, 15.2, 15.6 and 16.4/16.9:
external control and original source custody (FI-A02/FI-I03) remain inseparable
from independent helper evaluation and false-stop accounting (FI-A08/A13/A18).

## Install every contract in the first image

For an independently selected joint credibility policy:

```rust,ignore
let (owner, roles) =
    FileOversight::create_joint_mediated_andon_guarded_with_learned_generation_reserved(
        directory,
        profile,
        &guards,
        credential_registration,
        initial_topology,
        evaluation_protocol,
        joint_policy,
        &accounting,
        learned_config,
        RecoveryReserve::terminal(),
    )?;
```

`create_mediated_andon_guarded_with_learned_generation_reserved` supplies the
corresponding marginal-evaluation composition; it omits the `joint_policy`
argument. Both validate the original recipe, guards, graph, evaluator,
accounting configuration and event reserve before creating storage. One first
canonical replacement must acknowledge before the owner and separate
`FileMediatedRoles` escape.

The returned human, evaluator and topology-observer roles have distinct
purposes. Startup supplies no fresh source observation, certified cut, label,
helper judgment or human approval. The graph starts uncertified. Each actual
publication still follows the original topology/source checks and both review
keys. Configuring a joint policy does not qualify a candidate helper weight set.

Required raw or owned predictors and recipe-owned held-out joint publication
policies remain outside this composition. Their separate observer or evaluation
contracts cannot be dropped to make bootstrap succeed. Existing plain and
marginal mediated APIs retain their original behavior.

## Recover one original history under complete independent expectations

The new sealed `FileMediatedAndonLearnedRecovery` is exported from
`guarded::evaluation::andon::learned`. Begin it with:

```rust,ignore
let mut recovery =
    FileOversight::begin_open_mediated_andon_guarded_anchored_with_learned_generation(
        directory,
        profile,
        &accounting_requirements,
        &topology_requirement,
        &evaluation_protocol,
        &learned_config,
        &retained_history,
    )?
    .require_recovery_reserve(RecoveryReserve::terminal())?;
```

The independently retained `FileAndonRecoveryRequirements` still binds the
complete base guards, current policy, credential epoch, counter floors,
original Andon configuration, complete window inventory, minimum evaluation
revision, optional joint policy and publication contract. `None` continues to
mean required absence. `FileTopologyRequirement` additionally binds the exact
original graph, current graph and expected availability.

Recipe, history-anchor, graph inventory, evaluation, joint-policy, accounting
and publication mismatches refuse before the first numerical replay event.
The original replay checks every intervening transition. Current availability,
all guard states and independent floors must pass before Ready and again before
any finalizer. A failed complete check remains failed; changing caller data
cannot repair the private candidate.

`advance` retains the exact predecessor and finite event allowance of the
original `FileLearnedRecovery`. No inner cursor, mutable machine, evaluator or
topology role can be extracted early. Dropping even a Ready cursor changes no
canonical or pending bytes. Event quanta do not make an individual numerical
event or final filesystem synchronization preemptible.

## Resume with fresh custody or apply terminal Stop

`finish` acknowledges the original recovery Fence before issuing fresh separate
roles. It preserves numerical spending, labels, pending and censored cases,
Andon windows, costs, incidents and unresolved effect liabilities. The original
numerical owner stays paused; old approvals, clocks, identity eligibility and
topology availability stay withdrawn.

The caller must retain and validate its topology-source checkpoint separately.
Matching a graph does not prove source continuity or grant a fresh cut. The live
source workflow must bind that exact checkpoint to the same history, preserve
spent source work and certify the required new source before publication.

Original Message and Finish selectors inspect the fully verified history before
the recovery Fence. Finish still names its exact accepted Message predecessor;
equal output text cannot substitute for that receipt.

At Ready, an authenticated Stop can instead consume the cursor into the native
clock-independent admission Stop/Fence path. This returns no live observer or
evaluator. The original terminal reserve and conservative unknown-effect
accounting remain authoritative. A stopped history and its matching source
checkpoint are retained through the existing terminal checkpoint law; a lost
reply cannot justify retrying an effect or replenishing either budget.

The graph remains an operator-declared model. This composition does not establish
operating-system containment, authenticated completeness of that model, detector
quality or production qualification. Required compilation and runtime evidence
are recorded separately in `IMPLEMENTATION_STATUS.md`.
