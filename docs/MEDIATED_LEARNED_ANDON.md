# Learned publication with topology and independent accounting

Learned generation can retain topology enforcement, independent evaluation and
Andon accounting in the same durable owner. This composition keeps the original
numerical recipe, graph checker, evaluator, accounting reducers and canonical
writer. It introduces no journal format, alternate numerical replay or new
publication authority.

The work serves FA-026/073/105 under plan §§9.9, 11.2, 15.2, 15.6 and 16.4/16.9:
external control and original source custody (FI-A02/FI-I03) remain inseparable
from independent helper evaluation and false-stop accounting (FI-A08/A13/A18).

## Install every contract in the first image

For an independently selected joint credibility policy:

```rust,ignore
let (owner, roles) =
    FileOversight::create_joint_mediated_andon_guarded_with_learned_generation_reserved(
        directory,
        profile,
        &guards,
        credential_registration,
        initial_topology,
        evaluation_protocol,
        joint_policy,
        &accounting,
        learned_config,
        RecoveryReserve::terminal(),
    )?;
```

`create_mediated_andon_guarded_with_learned_generation_reserved` supplies the
corresponding marginal-evaluation composition; it omits the `joint_policy`
argument. Both validate the original recipe, guards, graph, evaluator,
accounting configuration and event reserve before creating storage. One first
canonical replacement must acknowledge before the owner and separate
`FileMediatedRoles` escape.

The returned human, evaluator and topology-observer roles have distinct
purposes. Startup supplies no fresh source observation, certified cut, label,
helper judgment or human approval. The graph starts uncertified. Each actual
publication still follows the original topology/source checks and both review
keys. Configuring a joint policy does not qualify a candidate helper weight set.

Required raw or owned predictors and recipe-owned held-out joint publication
policies remain outside this composition. Their separate observer or evaluation
contracts cannot be dropped to make bootstrap succeed. Existing plain and
marginal mediated APIs retain their original behavior.

## Recover one original history under complete independent expectations

The new sealed `FileMediatedAndonLearnedRecovery` is exported from
`guarded::evaluation::andon::learned`. Begin it with:

```rust,ignore
let mut recovery =
    FileOversight::begin_open_mediated_andon_guarded_anchored_with_learned_generation(
        directory,
        profile,
        &accounting_requirements,
        &topology_requirement,
        &evaluation_protocol,
        &learned_config,
        &retained_history,
    )?
    .require_recovery_reserve(RecoveryReserve::terminal())?;
```

The independently retained `FileAndonRecoveryRequirements` still binds the
complete base guards, current policy, credential epoch, counter floors,
original Andon configuration, complete window inventory, minimum evaluation
revision, optional joint policy and publication contract. `None` continues to
mean required absence. `FileTopologyRequirement` additionally binds the exact
original graph, current graph and expected availability.

Recipe, history-anchor, graph inventory, evaluation, joint-policy, accounting
and publication mismatches refuse before the first numerical replay event.
The original replay checks every intervening transition. Current availability,
all guard states and independent floors must pass before Ready and again before
any finalizer. A failed complete check remains failed; changing caller data
cannot repair the private candidate.

`advance` retains the exact predecessor and finite event allowance of the
original `FileLearnedRecovery`. No inner cursor, mutable machine, evaluator or
topology role can be extracted early. Dropping even a Ready cursor changes no
canonical or pending bytes. Event quanta do not make an individual numerical
event or final filesystem synchronization preemptible.

## Resume with fresh custody or apply terminal Stop

`finish` acknowledges the original recovery Fence before issuing fresh separate
roles. It preserves numerical spending, labels, pending and censored cases,
Andon windows, costs, incidents and unresolved effect liabilities. The original
numerical owner stays paused; old approvals, clocks, identity eligibility and
topology availability stay withdrawn.

The caller must retain and validate its topology-source checkpoint separately.
Matching a graph does not prove source continuity or grant a fresh cut. The live
source workflow must bind that exact checkpoint to the same history, preserve
spent source work and certify the required new source before publication.

Original Message and Finish selectors inspect the fully verified history before
the recovery Fence. Finish still names its exact accepted Message predecessor;
equal output text cannot substitute for that receipt.

At Ready, an authenticated Stop can instead consume the cursor into the native
clock-independent admission Stop/Fence path. This returns no live observer or
evaluator. The original terminal reserve and conservative unknown-effect
accounting remain authoritative. A stopped history and its matching source
checkpoint are retained through the existing terminal checkpoint law; a lost
reply cannot justify retrying an effect or replenishing either budget.

## Use the live learned service

The single-request learned command can retain this complete composition through
actual generation, native or process review, independent human approval and
later independent case assessment:

```sh
supervise_publication create-learned-generated CONFIG LEARNED_RECIPE REVIEWER_PROFILE \
  --actor-profile ACTOR_PROFILE --topology-profile CREATE_TOPOLOGY \
  --andon ANDON_PROFILE --evaluator-profile EVALUATOR_PROFILE \
  --retain-history-anchor /absolute/independent/first-history.anchor
```

`CREATE_TOPOLOGY` uses the existing
[topology creation profile](TOPOLOGY_SUPERVISED_CREATION.md), with an explicitly
selected new `retain_checkpoint` destination. Both that source checkpoint and
the independent history output are mandatory for this evaluated composition.
The Andon profile may be marginal `/1` or explicit joint `/2`; a joint policy
is installed in the original first image, separately from the topology graph.
A recipe-owned held-out publication policy still requires its own composition.

If a service listener fails after the first image was acknowledged and its
topology source was bound, creation reports the error and attempts to retain
the selected history and source checkpoints. After correcting the listener
conflict, use that pair with `--continue-generation`, a continuation topology
profile and two new output paths. An earlier refusal during preflight produces
no recovery pair.

The original source is attached to the same supervised driver and certified
before generation or request work. The original cut checks remain required
through review and publication. Independent evaluation runs only under the
remaining invocation and accepted-request deadlines after the original workflow,
without obtaining a new source, rerunning helpers or supplying an effect key.
Evaluator retirement precedes capture of the final source/history pair, so late
acknowledged labels are retained in that pair.

For an explicitly selected next Message:

```sh
supervise_publication create-learned-generated CONFIG NEXT_RECIPE REVIEWER_PROFILE \
  --after-message PREVIOUS_REQUEST --actor-profile NEXT_ACTOR_PROFILE \
  --topology-profile NEXT_TOPOLOGY \
  --andon CURRENT_ANDON_PROFILE --evaluator-profile EVALUATOR_PROFILE \
  --history-anchor /absolute/independent/first-history.anchor \
  --retain-history-anchor /absolute/independent/next-history.anchor
```

`NEXT_TOPOLOGY` uses the existing
[continuation profile](TOPOLOGY_SUPERVISED_CONTINUATION.md). Its
`source_checkpoint` must be the independently retained v2 checkpoint whose
embedded history anchor exactly matches `--history-anchor`. It must also name
a new `retain_checkpoint` output. A hand-entered graph or legacy source-work
floor cannot replace this paired custody. The saved source checkpoint must
cover the complete selected journal extent before event zero.

The same complete route supports `--continue-generation` for original
interrupted numerical work and `--finish-after-message PREVIOUS_REQUEST` for an
explicit Finish. Original recipe, topology, rights/source work, accounting
windows, evaluation floor and any joint policy remain exact requirements.
Recovery does not renew numerical or source work. Fresh graph and inventory
generations, source certification, identity, helper review and human approval
still govern subsequent publication.

Authenticated Stop and the invocation deadline are checked before open, at
every replay boundary and at Ready. An admitted Stop uses the original terminal
path, issues no evaluator or live observer and retains the acknowledged
source/history pair. Ordinary recovery captures its new Fence pair before
attempting fresh source binding. A missing next document, unavailable source or
later startup failure therefore retains that acknowledged recovery point in
the new selected outputs, while preserving the failure.

All selected source/history destinations are checked against the accounting,
topology, recipe, actor/reviewer and other profile inputs, the authority store
and every service endpoint before the first clock or storage creation.
Optional prechecks and the existing operator pair retain their original
contracts. Required predictors, campaign governance and a separate held-out
publication policy remain outside this mediated evaluation grammar.

## Evaluate retained topology-protected history

Independent truth can arrive after the original service has stopped. Select the
same original Message or Finish, accounting contract and retained source/history
pair explicitly:

```sh
supervise_publication create-learned-generated CONFIG ORIGINAL_RECIPE REVIEWER_PROFILE \
  --evaluate-only --actor-profile ORIGINAL_ACTOR_PROFILE \
  --topology-profile HISTORY_TOPOLOGY \
  --andon CURRENT_ANDON_PROFILE --evaluator-profile EVALUATOR_PROFILE \
  --history-anchor /absolute/independent/retained-history.anchor \
  --retain-history-anchor /absolute/independent/evaluated-history.anchor
```

For a recorded Finish, also select `--finish-after-message PREVIOUS_REQUEST`
and its original request/recipe binding. `HISTORY_TOPOLOGY` uses the existing
continuation profile with the exact v2 `source_checkpoint` paired to the input
anchor and a distinct new `retain_checkpoint` output. Both marginal and joint
Andon profiles retain their complete independently selected contracts. The saved
source checkpoint must cover the complete selected journal before replay; an
older pair cannot omit later source expenditure.

The original sealed recovery cursor verifies numerical provenance and selects
the recorded request before its sole Fence. The returned topology observer stays
unbound throughout assessment. No current evidence, helper weights, next graph
or inventory document is opened, and no source operation is purchased. Original
model/codec assets and the independently retained historical inputs remain
necessary for replay. Only the evaluator and authenticated Stop endpoints are
served; no actor or human-approval listener is opened.

After evaluator retirement, the original observer carries its unchanged source
documents, work and last operation into the new checkpoint. The checkpoint and
history output include the same acknowledged assessments and terminal Stop.
The restricted [historical checkpoint rule](TOPOLOGY_WORK_CHECKPOINT.md#historical-evaluation-successors)
permits only evaluation/time and original terminal events after the recovery
Fence. It cannot conceal source, numerical, policy or publication successors.
Availability stays withdrawn; a later live continuation must bind newer source
generations and pass the original source checks and fresh independent review.

A listener failure after fencing attempts to retain the new Fence pair while
preserving the error and the existing listener. Correcting that conflict and
selecting the new pair can reopen the same pending case. Output validation occurs
before clocks and recovery, and each output remains create-only. Retention is a
separate fallible operation; a partial export is not an acknowledged pair.

This supplies late-label custody rather than new publication authority. The
regressions are authored and source reviewed; required RCH compilation and
runtime qualification remain pending.

## Serve a resident learned sequence

`serve-learned-generated` accepts the same topology, Andon and evaluator
profiles with a resident sequence manifest. The first entry holds the single
topology selection for the invocation. The same driver certifies each release, keeps
the original observer's work counters across handoffs, and retains the
evaluator through the final case. Both output destinations are checked against
the scheduled role paths and direct inputs before loading numerical assets.
Nested asset reads also check those destinations.

For recovery, select the remaining manifest with `--after-message` or
`--continue-generation`, the original history anchor, and the v2 topology
profile naming its matching source checkpoint. A sole remaining Finish uses
`--after-message` with that release in the manifest. One cooperative recovery
Fence covers the suffix. Each remaining effect still requires fresh
certification, helper review and human approval. See the
[resident creation and recovery commands](RESIDENT_LEARNED_PUBLICATION.md#retain-topology-through-a-resident-evaluated-sequence).

The graph remains an operator-declared model. This composition does not establish
operating-system containment, authenticated completeness of that model, detector
quality or production qualification. Required compilation and runtime evidence
are recorded separately in `IMPLEMENTATION_STATUS.md`.
