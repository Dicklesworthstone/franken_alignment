# Policy promotion with retained topology-source custody

The explicit [learned policy governor](LEARNED_POLICY_GOVERNANCE.md) now admits
nonpredictive learned text-stream histories whose original publication path
requires topology mediation. Promotion uses the same complete numerical replay,
campaign comparison and native Request/Approve/Promote transaction as the plain
profile. The independent topology requirements and source-work checkpoint remain
mandatory throughout; no unmediated owner is recovered along the way.

This is trusted local maintenance authority. The actor, native helpers and human
effect reviewer do not receive governor authority. No signed governor identity,
predictive policy-promotion profile or operating-system containment claim is
introduced by this composition.

## Explicit paired selection

The campaign guard must already exist in the original first image, with exact
independently selected limits in `fa.learned-recovery-policy/2`. First obtain and
review the complete existing `--policy-replay` output with the same retained
history and topology profile. The governor request remains the strict
`fa.learned-policy-promotion/1` schema; its original revision, control sequence,
authority epoch, candidate, full reviewed report and explicit relaxation
acceptance keep their existing meaning.

Invoke the original promotion mode with both topology arguments:

```text
supervise_publication create-learned-generated CONFIG RECIPE \
  --promote-policy GOVERNOR_REQUEST \
  --history-anchor INPUT_HISTORY \
  --retain-history-anchor NEW_HISTORY \
  --topology-profile RETAINED_TOPOLOGY_PROFILE \
  --retain-topology-checkpoint NEW_SOURCE_CHECKPOINT
```

The topology profile must be `fa.mediated-submit/2`, naming an independently
retained `TopologyCheckpoint`. Its embedded history anchor must equal the
separately selected input history anchor. Manual v1 work minima cannot establish
the complete source cut and are refused. The ordinary v2 `next` selection is
parsed but its live files are never opened or refreshed in this maintenance
mode. The profile itself and retained checkpoints must be outside the authority
store. Historical profiles must not select their own live `retain_checkpoint`.

Both output destinations are explicit, distinct new files outside the authority
store. A topology profile without its paired output, an output without its
profile, duplicate options or any unrelated live/receipt/recovery mode refuses
before mutation. The plain command keeps its existing grammar and result format.

## The original authority and source checks

The native entry point is
`FileMediatedLearnedRecovery::require_policy_promotion_checkpoint(request, saved)`.
It consumes the original unreplayed cursor into
`FileMediatedPolicyPromotionRecovery`, which has no live `finish`, unwrapping,
observer or governor operation. The original terminal reserve must already be
present. Independently supplied recovery floors are retained or strengthened by
the checkpoint floors, never replaced by a weaker historical cut.

Before replay, the source checker accepts only:

- The exact retained source/history cut.
- That cut followed by the exact selected campaign's complete
  Request/Approve/Promote triple, for recovery after a lost acknowledgment or
  failed output export.

An intervening numerical event, source check, graph update, clock event, recovery
Fence, unrelated campaign or partial campaign cannot explain missing source
custody. The original full numerical replay still validates every event. The
policy review is captured at the original selected predecessor during that same
pass, including on a retry; there is no second numerical replay for governance.

Ready and finalization check the original complete graph requirements, optional
marginal evaluator, guard inventory, current effective policy, credential epoch
and recovery floors. A trusted governor must compare the complete original
report with the independently reviewed bytes. Missing observations still require
shadow evaluation; explicit acceptance of newly reviewable cases cannot waive
them.

For fresh promotion, the original native Request/Approve/Promote events consume
ordinary journal capacity and are persisted together in one canonical
replacement. Complete mediated requirements and source custody are checked both
before preparation and on the validated successor. Only the effective policy
expectation advances to the actual native receipt's candidate; other independent
requirements remain unchanged. The terminal reserve cannot fund the campaign.

The original policy transition cancels only undispatched reservations and
withdraws old approvals. Admitted and Unknown effects remain charged. There is
no recovery Fence, clock acquisition, source refresh, resumed numerical work,
helper rerun or new publication. Retained graph availability is historical;
promotion does not certify a fresh cut or supply a publication permit.

## Acknowledged history and exact retries

`finish_promoted_policy` returns `FileMediatedPolicyPromotionHistory`: the original
immutable policy-promotion receipt and a `TopologyCheckpoint` for the same
acknowledged cut. Original source documents, spent checks/read bytes and last
source operation remain unchanged. Only the acknowledged history and native
control/authority floors advance.

Mediated command output uses `fa.learned-policy-promotion-result/2`. It retains
the original outcome/accounting fields and adds explicit topology-checkpoint
retention, revision, spent checks/read bytes and last source operation. Plain
promotion continues to emit `fa.learned-policy-promotion-result/1`.

After acknowledgment the operator attempts both independent archives and the
result report, even if one destination fails or the original deadline has
elapsed. A failure cannot undo promotion. Keep the original governor request,
candidate, reviewed report and input pair, independently select the acknowledged
**current effective policy**, and retry with new paired output paths. The native
retry requires the original full review, policy update and acceptance bit and
appends zero events. A successfully exported current pair can also be used for
the same exact retry or ordinary historical recovery.

Canonical storage or allocation failure can leave acknowledgment unconfirmed.
The same exact-request recovery distinguishes the unchanged predecessor from
its complete original promotion triple; it cannot adopt a partial campaign or
rebase the request onto later unretained work. Custody is still an external trust
assumption, not authentication or protection against joint rollback of all
retained records.

## Scope and regression sources

This is a bounded composition under FA-130 and plan §§22.2, 22.4 and 22.7
(FI-A14/FI-A18), with the original FA-073 declared mediation and source-custody
contracts. No new journal event, source-checkpoint wire format, dependency,
runtime or authority role is introduced.

Six public native regression functions cover actual mediated generation and
native/human publication, Unknown liabilities versus reservations, exact retries,
all original guard/floor requirements, foreign/earlier source cuts, ordinary
capacity versus terminal reserve, canonical changes, staging failures and
pre-replay selection. Five operator regression functions cover the full argv and
independent profile loaders, complete reviewed reports, current-policy retries,
paired archive failures, late deadlines, report-output failures, manual/stale
source custody and predictive refusal with a permitted nonpredictive control.
The original common promotion reducer retains its five storage-barrier tests.

These are authored regression sources, not executed qualification. Required
RCH compilation, tests, formatting and Clippy must run against the resulting
revision before execution credit is assigned. Fixture models and declared graphs
do not establish detector quality, policy quality, physical mediation, independent
governor authentication or completion of the broader campaign/shadow work.
