# Pre-payload forecasts bound to actor request keys

`FileConsistencyObserver::forecast_request` predicts before the actor payload is supplied, using the existing independent observer role and original native predictor. It accepts the external request key, not a guessed internal attempt ID. The original `RequestBook` allocation expression is factored into one read-only helper shared with admission: prior direct attempts and previously refused requests both participate. No alternate allocator or rights ledger is introduced. Forecasting reserves neither effect units nor a new request record.

A successful keyed forecast retains its external key and derived internal attempt in the original replay machine. Only that request may consume it. A different external key or a raw direct proposal refuses before observation and leaves the usable owner and pending forecast intact. The same check runs during semantic replay, so a well-formed input journal cannot steal the forecast by skipping the live facade. The older explicit raw-attempt forecast API remains unchanged when no keyed forecast is outstanding.

The matched request still uses the original request book and broker. If it consumes its valid observed category but downstream admission refuses, the request result and lifetime evidence commit together, the binding clears, and the allocator retains that refused attempt. Exact retries use the original request disposition without another forecast, sample or snapshot, including retries while a different new key has a pending forecast. Changed action bytes conflict with the original key. If a matched request becomes terminal without consuming its expired/stale forecast, coverage is marked lost and the original pending identity remains; it cannot be recycled as a fresh trial.

`pending_forecast_request` is supervisor-only data and returns the outstanding external key, if any. The existing native snapshot still supplies its internal pending attempt. Recovery retains this binding and the original lifetime evidence. The predictive recovery fence treats unanswered forecasts as lost coverage and returns a fresh observer role, never a new error budget. At a clean boundary a fresh observer may predict the next request after a new clock and strictly newer capture sequence. Source acquisition, actor isolation, congress review, separate human approval and first-publication checks retain their original obligations.

Four public regressions cover an actual actor gateway with external key 9000 allocated to attempt 41 after a previous terminal denial, followed by original congress/human-key publication and reconciliation; consumed admission refusals and exact retries while another key is pending; terminal expiry and recovery; and clean recovery with new observer custody and capture-sequence rejection. Three unit functions cover ten existing Store replacement barriers across forecasting and request intake plus well-formed journal theft rejected by semantic replay. These are source tests, not reported passing execution.

The only new encoding is subtag 3 within existing consistency input family 28. Earlier records are byte-compatible. The original current configuration, native predictor, likelihood arithmetic, effect accounting and old regression assertions are not weakened. A rejected encoding occurs before action observation; prediction/classification entry still sets the existing unavailable latch before any candidate execution. An I/O failure exposes no speculative binding, admission result or evidence update.

RCH verification was attempted and exited 127 before compilation because `rch` is unavailable. Rust compilation, rustfmt, Clippy and unit/integration/doctest execution remain pending. Owned-source identity and patch whitespace checks are not Rust qualification. Labels, calibration, capture provenance and external clock remain assumptions. There is no new runtime/dependency, production admission or Beads closure. Uncommitted external capture gaps still require independent operator knowledge; canonical recovery cannot establish that no such gap occurred.
