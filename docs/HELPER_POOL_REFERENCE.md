# Nonblocking helper pool and end-to-end congress delivery

Consumer: the existing oversight congress receiving independent member responses through preprovisioned Unix streams. This completes the transport/coordinator reference slice introduced in HELPER_WORKERS_REFERENCE.md and HELPER_IO_REFERENCE.md, serving FA-018/FA-019/FA-107, plan sections 9.1 through 9.3, and FI-A03/FI-A06/FI-A13/FI-A14/FI-A16. It does not close the complete production work packets or qualify their missing foundation dependencies.

## Connection and scheduling contract

`HelperPool::new` receives the original ObservedSession and an exact member-to-UnixStream map from the trusted supervising host. The map must equal the entire frozen roster; missing and extra transports refuse before any input bytes are sent. Every stream is put in nonblocking mode. The pool owns the original HelperRound and one HelperConnection per member. It exposes no socket replacement, reduced-roster fallback, mutable-session access or operator-supplied replacement verdict.

A pump takes one bounded I/O step for every member, including when an earlier member is blocked, disconnected or malformed. It returns each connection result and the original coordinator's worker status, only to the supervisor. Every valid response still traverses the existing commitment, reveal, transcript replay and reducer. Failure remains missing in that reducer; it never becomes an abstention or a fabricated vote. No helper can publish an effect merely by sending Allow. The returned ObservedReview must pass the original broker's current input, policy, authority and dispatch prerequisites.

`pump(now)` declares one atomic logical-tick batch for controlled-time hosts. Real elapsed-clock hosts use `pump_with_clock`, which reads the trusted controller-domain clock before and after every nonblocking I/O step. A commitment read while the clock crosses the exact commit cutoff is refused at the post-I/O observation, not backdated to the beginning of the batch. The same rule covers reveals. A backward clock observation returns Stale and does not roll back prior progress; a queued but unaccepted response still expires normally. The callback is a trusted host scheduling interface, never a timestamp field supplied by a helper.

`ready_to_finish` and `next_deadline` are supervisor scheduling hints, not epistemic claims about an action or permission. `finish` performs no I/O, inferred clock advancement, helper retry or vote replacement. A premature finish keeps the session available; a completed review is the original non-rebindable review. There is no hidden executor, listener, subprocess launcher, credential provider or second authority ledger.

The reference implementation deliberately favors the existing simple coordinator over an optimized scheduler. A fresh-clock pump invokes the bounded whole-roster advance operation around individual I/O steps, so it can make O(m^2) slot checks for m members. Its roster, request frames, salt replies and per-step I/O remain bounded. These are not throughput, memory-allocation or latency measurements, and no production SLO is claimed.

## Executable scenario sources

The Unix process tests launch the integration test binary in separate helper subprocesses, connect each to its assigned socket, decode the exact authorized input, and have a deterministic fixture inspect those bytes before choosing a verdict. This is actual process/socket test code rather than tests that inject votes into the supervisor session. The fixture is not a trained model or an empirical safety classifier. The child environment is explicitly seeded with a fake effect credential and then cleared by the launcher; the child asserts its absence. That checks this test launcher's environment filtering, not general credential isolation or hostile-process containment.

The positive process scenario runs both helpers, completes the original congress, obtains the original one-shot permit, publishes real temporary-file bytes, deliberately loses the publication acknowledgment, then terminates the worker processes. With helper inputs unavailable, it reopens the existing file endpoint under a new dispatcher fence and reconciles the original Unknown effect to Confirmed without rerunning a helper, acquiring a replacement permit or publishing twice. The existing FileEndpointRecovery key and in-memory controller must survive; this is not process-independent authority recovery.

Negative process scenarios pair the same healthy second helper with a first helper that reports Hold, withholds its reveal, substitutes a reveal salt, or sends an invalid commitment frame. The healthy peer must finish in all cases, while the missing or adverse evidence prevents permission. A silent connected socket test checks that another member still progresses and the unchanged deadline closes the missing-member case. Missing and extra stream-map entries cannot redefine the roster.

Separate receipt-clock tests use real socket bytes with near-identical timing arms. A commitment is accepted when the post-read clock remains before the cutoff and refused when the cutoff is reached during the same operation. A clock rollback after receipt preserves pending work without letting that work bypass later expiry.

The interoperability tests compose the concurrently added `HelperClient` with `HelperPool` over socket pairs. Profile-matched clients receive their exact original input, perform one deterministic fixture evaluation each, and send frozen commit/reveal replies through the original publication path. A changed model epoch is rejected by the actual client before inference; closing that client's stream leaves it missing while its healthy peer completes. The tests do not replace or modify the client implementation.

## Remaining trust and verification boundaries

The host provisions, authenticates and isolates the connected peers. Same-user subprocesses and a cleared environment are not a sandbox. No actual model/provider execution, peer identity, OS containment, side-channel independence, cryptographic commitment, durable authoritative ledger or production Asupersync integration is qualified by this reference transport. The existing FNV comparison remains explicitly non-cryptographic. A malicious helper may lie about faithful use of its input; this machinery binds protocol evidence without proving helper truthfulness.
