# Write-ahead sending and restart-safe actor clients

`FileActorClient`, `FileActorConnection` and `FileClientProfile` live in `delivery::persistent::observed::stream::actor_wire::client`. They support both original raw proposals and encoded stream intents through the same `ActorClient` implementation. No server request allocator, outcome reducer, wire command, source provider or effect authority is added. Use a private client directory distinct from every server publication directory. The profile fixes the original client limits, image capacity and an independently provisioned exact server/transport binding. Connection authentication, file integrity and single-writer custody remain operator responsibilities.

Creation and opening use the original exclusive `Store`. Opening checks the complete bounded image, canonical directory identity, exact profile and independent minimum revision before cleanup. It sends nothing and restores no transport-local ticket. Explicit exact Submit retries reacquire visibility. A changed deadline, target, payload or epoch cannot replace a retained request, even after the server has advanced its stream prefix. A successful child restart, client reconnect or missing response never establishes nonexecution.

Preparing Submit/Poll/Cancel/Retry calls the original client preflight, then acknowledges its recovery image before returning. Preparation performs no socket I/O. Each subsequent step first commits a separate intent with the absolute maximum work of that one original bounded I/O step. Only then does the original client read/write/flush. A second canonical replacement stores its actual counters and accepted response or failure before returning any result. Unused reservation is released only after that second acknowledgment. Failed replacement or encoding closes the connection; a caught unwind leaves the owner unavailable and blocks reentry. A due in-flight result cannot fall back to an older apparent success.

A crash between those boundaries leaves an exact unresolved command and reserved step ceiling. Recovery conservatively consumes the full ceiling, without inventing a response or resending fragments. Saved request counts, payload allowance, exchange limits and I/O work do not reset. Reservations are distinct from completed work: `FileActorClient::read` inspects both alongside historical responses, original requests and failures beside a locked or faulted owner. It obtains no writer, cleans no staging files and exposes no connect/send method. A stored reservation alone is not proof any bytes reached the peer. An absent response is not proof an effect did not execute. Protect the independent revision floor against rollback; no equal-counter fork authenticity is claimed.

This deliberately uses two synchronous canonical replacements per I/O step, plus a preparation write. It prioritizes explicit crash behavior, not throughput or wall-clock latency. The host supplies bounded/nonblocking I/O and schedules calls; there is no background task, retry loop, hidden executor, network authentication or independent watchdog. A supplied Unix stream must already be nonblocking and authenticated to the selected server. The existing client recovery codec refuses unlisted I/O error kinds rather than erasing their meaning; such an encoding refusal leaves the write-ahead intent unresolved.

Six unit regression functions cover fifteen original Store barriers at intent, partial-write completion and response completion; caught write interruption; retained budget exhaustion; exact domain/limit/path/floor checks before staging cleanup; capacity refusal without I/O; successful response publication and exclusive ownership. Two integration regressions use actual Unix sockets and the original full-input/two-key FileOversight path: a lost client reply followed by server execution and exact-key recovery without a second effect, plus an old stream-intent retry after prefix advancement followed by a separately reviewed explicit finish. All tests are source additions, not passing executions. RCH is absent here; compilation, rustfmt, Clippy, tests and doctests remain unexecuted. No dependencies, original assertion semantics, server journal formats, Beads states or qualification gates change.
