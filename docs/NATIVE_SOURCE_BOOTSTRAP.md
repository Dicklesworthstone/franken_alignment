# Atomic source-backed native startup

## Contract

`create_generated_text_stream_from_source` establishes the model, monitor,
sampler, tokenizer, native-only stream, mandatory file evidence source, logical
recovery reserve and selected publication requirements in one first canonical
replacement. `GeneratedSourcePublication` represents stream-only, witness-checked
and joint-qualified publication selections without dropping their distinctions.
`GeneratedSourceProfile` pairs that selection with the mandatory source policy.

This closes the model-only bootstrap cut left by creating a native owner and then
calling `enable_file_source` as a second transaction. No successfully acknowledged
initial image from the new constructor lacks the declared source requirement.
Failure before rename can still leave a directory or staging file without a
canonical image; ambiguous directory sync can leave a complete image. No role is
returned on either failure. This is the original local Store's replacement law,
not a filesystem transaction spanning directories or a power-failure experiment.

Construction does not open evidence files, compute tokens, create a text intent,
invent a fresh clock or admit an effect. Actual observation and original
numerical admission remain separate. A model-only legacy image is not repaired by
silently selecting a source after recovery. A missing original generation intent
also remains missing; these APIs do not create or resume one implicitly.

`open_generated_text_stream_from_source` checks the source identity, scope,
limits, freshness and selected current registration generation against the same
locked image as the stream, reserve, witness/joint requirements, model and
tokenizer. Configuration mismatches reject before full numerical replay,
`confirm_and_cleanup`, owner/reviewer creation or the recovery fence. Complete
matching older journals with a separately installed source remain compatible.

A source replacement can change its registration generation, not identity,
scope, retention limits or lease. Preflight projects the last requested generation
only for early comparison; the original reducer still validates every replacement
and governance predecessor. After replay the actual effective policy is checked
again. Selecting an old generation cannot reset the registration, and an exact
historical replacement retry cannot grant a fresh capture or allowance.

Successful recovery still uses the original authority fence. It preserves
acknowledged prompt/progress, RNG and resource spending, confirmed publication
and unresolved liabilities; it pauses inference, withdraws source eligibility
and old keys, and does not restore active qualification. New work still requires
fresh source/time, explicit resume, whole-input helper review, an independent
human key and any selected final-publication witness checks.

This extends the existing L1/L2 source registration and L4/L5 native publication
composition, serving the plan's §§8.7, 11.2 and 16.4 recovery contracts. It adds no
new event encoding, evaluator, numerical implementation, rights ledger or runtime
dependency. Independently anchored or guarded-role deployments still require
their separately composed openers; matching configuration is not authentication
of a file, trained detector quality, anti-rollback protection or OS isolation.
