# Identity probes from the controller-owned model

`OversightBroker::hosted_identity_probe(expected_actor_revision, passport, measurement_sequence, budget)` derives a pristine DecoderIdentityProbe from the SAME immutable model parameters retained by its owned MonitoredSampledDecoder. There is no separate model argument and no mutable model getter. A missing numerical owner, stale actor revision or incompatible passport refuses. The private sampled-host bridge shares only immutable model data; it does not export the live token history, cache, logits or sampler.

Advancing that probe executes registered stimuli in private fresh caches. The original identity observer still performs comparison and installation. A pristine probe can also feed the existing FileIdentityObserver decoder adapter, but that does not by itself establish that two distinct authority owners represent the same deployment. The host must provision their correspondence explicitly. A probe contains observations, never effect rights or an authentication signature. Its IdentityProbeWork is separate from live decoder work, monitoring budgets and the effect ledger; inspection does not misattribute experimental computation to the live actor.

The actor position, sampled draws, monitoring state and live numerical-work counters must remain unchanged by probing. A separate case covers missing owner, stale revision and foreign tokenizer, paired with valid preparation and unchanged resource accounting. These tiny fixtures do not measure trained-model discriminatory power.

A new unit regression drives the durable numerical runner through 15 deterministic storage-failure scenarios: matching measurement, installation and actual numerical mismatch, each at Stage, Write, FileSync, Rename and DirectorySync. It uses the original Store fault seam and original identity fixture. Original identity tests are unchanged except for one child-module registration. These scenarios are not hardware power-cut evidence.
