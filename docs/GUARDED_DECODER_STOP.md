# Automatic stopping in the complete guarded owner

`FileGuardSet.decoder_stop` pins an optional original `HostedStopPolicy`. It can be present only with an owned decoder. `create_guarded` validates that combination before creating storage and includes the policy after the original numerical enable in the sole initial canonical image. No owner or privileged role is returned between those events. This does not change `FileDecoderConfig`, silently enable a stop policy on legacy journals, or add another authority ledger.

`open_guarded` compares the exact policy presence, ID, generation and stop-operation identity before numerical replay, alongside its existing full model/monitor/sampler comparison. None means the policy must be absent. Duplicate, missing or unexpected policies refuse without cleaning pending files, appending a recovery fence or returning roles. Full semantic replay subsequently validates the policy's original bootstrap and every numerical witness. The public guard struct now requires an explicit `decoder_stop` field; existing repository literals use None to preserve their original semantics.

The original numerical owner alone detects the trigger and attempts the stop. Its existing durable cleanup withdraws identity eligibility, pending campaign approvals, human effect keys and sendable envelopes in the triggering transaction. Already published complete messages remain visible and are not relabelled as a finished stream. The original stop/drain retains executed and uncertain liabilities; obtaining a fresh role bundle cannot resume a terminally stopped decoder or turn an old campaign key into permission.

Four integration regressions exercise all guards with actual file evidence, numerical computation, full-input congress, separate human approval, credentialed message publication and continuation across restart; contrast this with a real monitor alarm while a human effect and policy promotion await execution; test each policy field and presence/absence against unchanged canonical/staged bytes; and pair invalid bootstrap with the valid owned-decoder control. These tests use the existing deterministic model and identity fixtures, not authenticated real-world inference providers.

Three unit regressions exercise 20 deterministic original Store barrier scenarios: initial publication, recovery fence, sampled-alarm transaction and failed checkpoint re-review, each at Stage, Write, FileSync, Rename and DirectorySync. They check no speculative owner/incident result, canonical-only recovery, no live retry after ambiguous failure, unchanged physical-work accounting on exact historical retries, no resume after a visible terminal stop, and stop draining while the source-interruption latch remains set. A further preflight case rejects duplicate stop configuration before numerical replay. No new storage fault seam or original assertion weakening was introduced.
