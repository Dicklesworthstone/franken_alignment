# Live evidence from compulsory decoder monitoring

Consumer: trusted control-plane admission that must distinguish a currently
reviewed numerical prefix from a copied historical quiet report (FA-011/025,
plan activation-monitoring and stop-before-effect contracts). This is actual
in-process inference provenance, not authentication of weights, detectors or an
external actor. It grants no effect authority.

`MonitoredDecoder::observation` returns a read-only handle bound to exactly that
owner. An empty prefix is unavailable. Before admitted numerical execution, the
owner invalidates its prior eligibility. Only complete, all-layer quiet review
publishes a new eligible original-token prefix. All input tokens are monitored;
there is no way to wrap an already-advanced raw session. NoAlarm is a numerical
observation, not a statement that the detector is adequate or the action is safe.

`capture` copies the original token IDs once and shares the final immutable
report. `validate` checks the original owner and exact current report without
copying tokens. Identical numeric identities, token histories or logits from a
second owner do not substitute. New computation stales previous snapshots;
holds, admitted numerical failures and owner loss withdraw eligibility. This
also holds when a numerical transaction fails without advancing its KV cache.
Invalid token, stale position and insufficient numerical-budget preflight leave
an unchanged, still-reviewed prefix eligible. A caught unwind after admission
leaves the source unavailable. Drop invalidation needs no RefCell borrow.

A snapshot intentionally survives for audit after owner loss, but cannot validate
as current. The source contains original tokens and the final report only, not
KV state, sampler state, logits, a writable monitor, or an effect permit. The
prefix is bounded by the existing model context. Capture does not preserve every
prior score trace; the compulsory non-resettable owner establishes that each
preceding step was quiet. Observer/evidence debug output omits token contents.

Six integration scenarios exercise actual numerical inference, owner identity,
quiet and held paths, budget exhaustion, preflight refusal, admitted arithmetic
failure and loss. Two internal lifecycle tests cover pre-execution invalidation
and Drop during a prefix borrow; one compile-fail example distinguishes evidence
from permits. These tests and source have NOT been compiled or executed here.
RCH verification remains pending; no execution evidence, dependency admission,
bead status, runtime, or detector qualification has been changed.
