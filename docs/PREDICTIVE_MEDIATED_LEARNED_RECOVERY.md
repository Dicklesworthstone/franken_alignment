# Predictive and mediated learned recovery

This profile composes the original required pre-output predictor, learned
generator, declared topology gate, optional marginal evaluator, and guarded
two-key publication owner. It closes the custody gap between the existing
predictive learned and mediated learned recovery profiles.

## Public contract

The types live in
`observed::guarded::mediated::predictive`:

- `FileMediatedPredictor::Raw(FileConsistencyConfig)` pins the original
  owned residual predictor.
- `FileMediatedPredictor::Owned(FileLearnedConsistencyConfig)` pins the
  original owned learned-K/V predictor, including its complete source mode,
  side, timing, representation, per-job and lifetime work, and inventory limits.
- `FilePredictiveMediatedRequirements` freezes the complete independent
  oversight requirements, initial and current graph, current availability,
  predictor variant/configuration, and optional marginal evaluation protocol.
- `FilePredictiveMediatedLearnedRecovery` is a sealed original learned
  recovery cursor. It exposes progress and bounded event replay; it exposes
  neither an inner owner nor roles before acknowledgment.

The `FileOversight` entry points are:

- `create_predictive_mediated_guarded_with_learned_generation`;
- `begin_open_predictive_mediated_guarded_with_learned_generation`;
- `begin_open_predictive_mediated_guarded_anchored_with_learned_generation`;
- `open_predictive_mediated_guarded_with_learned_generation`.

The constructor takes the original directory, profile, guard set, optional
credential registration, initial topology, explicit predictor, optional marginal
evaluation protocol, and learned configuration. The predictor must exactly equal
the corresponding required pre-output pin inside that learned configuration.
Unpinned, wrong-mode, supplied-capture and standalone predictor configurations are
not admitted. Existing ordinary mediated learned APIs keep refusing predictor
pins; a caller must explicitly select this combined custody profile.

The returned `FileMediatedRoles` has its consistency observer present.
Human, topology, optional identity/governance, and optional evaluator roles remain
separate original capabilities. Quiet prediction and numerical monitoring do not
grant either effect key.

## Atomic startup and exact recovery

Startup uses the original private guarded bootstrap. The sole learned Enable
installs its pinned predictor and any recipe-owned policy source. An independently
declared source must match that policy exactly; it is not installed twice.
Original native validation of all guards, predictor and topology completes before
storage creation. A single first canonical replacement precedes owner or role
issuance. No intermediate publication owner is returned.

Recovery opens the original exclusive `FileLearnedRecovery`, binds the exact
recipe and, for owned prediction, its original owned-history binder. The
independent anchor is compared with the same locked canonical bytes before
numerical replay. Preflight checks the exact topology and marginal evaluation
bootstrap and rejects alternate prediction routes, supplied captures, standalone
enables, sampled-decoder gates and joint evaluation profiles.

Every original event and numerical witness is replayed by its existing owner.
Before Ready, finish, or pending-reset completion, the full original guard,
effective-policy, credential and floor checks run alongside exact predictor mode,
complete owned fingerprint, latest registered graph and availability checks.
A final mismatch is sticky and cannot produce Ready or a write. Dropping an
unfinished cursor releases it without canonical replacement or pending cleanup.

The original single recovery fence pauses numerical work and withdraws topology
availability, old identity evidence and effect approvals. A returned observer is
new custody, not a current source, fresh forecast or certified cut.

## Reset and publication ordering

`finish_pending_reset` accepts only the independently retained exact
`FileLearnedResetIntent`. It checks all requirements around the same original
private reset preparation. Reset completion and recovery fence share the existing
canonical replacement. An exact completed-reset retry adds only the fence,
without another incident, audit or source acquisition.

The existing opt-in forecast reset-successor contract is unchanged. In its
permitted case, a checkpoint before prompt completion can resume on the original
monotone successor stream, accept a fresh prefill token and obtain a forecast from
that actual source. The public positive regression follows this order:

1. Complete the acknowledged pending reset through anchored cooperative recovery.
2. Supply fresh time, resume, and accept the original successor prefill token.
3. Register a newer graph and inventory and obtain the original native cut.
4. Acquire a raw or owned pre-output forecast under that authority epoch.
5. Run the original sampler and compare all draws/tokens with independent original
   generation; establish fresh identity for the resulting actor revision.
6. Admit the exact generated request and run the original source-bound sidecar
   probes and native model congress.
7. Obtain the independent human key alongside the automatic key, publish the
   actual generated bytes, and reconcile the original endpoint receipt.

A topology replacement advances authority epoch. Therefore it precedes the
fresh forecast in that flow. This profile does not carry a forecast across a
topology epoch change.

Unanswered/pending forecasts keep lost coverage across reset and recovery.
Owned acquisition work and retained source bytes stay spent. Exhausted lifetime
budgets stay exhausted. Answered but abandoned sampled output still prevents a
new sampling cycle after reset. Replaying the same RNG-derived output is not
promoted into a fresh conditionally calibrated observation by a new role, reset
or graph identifier. No alpha reset, free retry or new conditional calibration
contract is introduced.

Unknown dispatched effects remain charged and retain the graph certificate
bound at dispatch. Original reconciliation and sealing settle them without new
generation, forecast, cut or approval. New numerical work cannot erase this
liability.

## Regression coverage and validation status

The public target is
`crates/fa-reference/tests/mediated_predictive_learned_recovery.rs`.
Its eight authored tests cover:

| Boundary | Positive observable and causal refusal |
| --- | --- |
| Atomic configuration and custody | Raw/owned original creation and cooperative recovery; optional roles present/absent; no storage for unpinned, wrong-mode or invalid evaluation bootstrap; ordinary profile still refuses pins. |
| Complete reset-to-effect flow | Both predictor modes, exact anchored reset, successor stream, original sampled output, fresh graph, native review, independent evaluation and actual two-key publication; old roles and missing human publication refused; completed reset retry only fences. |
| Independent configuration | Exact predictor variant and owned budget, graphs, availability, evaluator, guards, effective policy and floors; rejected paths preserve canonical and pending bytes. |
| Exact anchors | Equal-counter forks and truncation refused before cleanup; exact anchor succeeds. |
| Unanswered forecast custody | Pending request, coverage loss, acquired work, retained bytes and sampled-work totals survive reset; no fresh generation or forecast. |
| Terminal finite experiment | Answered abandoned samples and zero owned lifetime remain terminal after reset. |
| Unknown effects | Dispatched but unpublished work stays charged after recovery; old keys/roles fail; original settlement releases only sealed unexecuted liability. |
| Topology changes | Clean and bypass graph controls change to the same epoch before forecasting. Both generate the same quiet original output and consume one forecast. The clean cut reaches native Allow and two-key publication; the bypass edge prevents original request admission without relying on old-key revocation. |

**These new tests and the two compile-fail examples have been authored and source
reviewed, but have not been compiled or executed in the implementation session:
the executor became unavailable.** Their listed outcomes describe assertions,
not reported passes. Prior results for the separate original profiles are not
evidence that this new combined target has run.

The fixtures use the existing tiny actual decoder, native helper model,
neutral probability table and declared graph controls, with their original
budgets. They establish executable regression intent, not empirical detector
calibration, helper independence or operating-system containment.
