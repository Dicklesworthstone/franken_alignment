# Bounded batching for the write-ahead actor client

`FileActorConnection::drive(revision, ClientDriveBudget)` uses the same original `ActorClient::drive` and exclusive `Store`. It acknowledges one conservative quantum reservation, advances only the already-prepared exchange, then saves actual work and the accepted response or error before returning. There are two canonical replacements per non-idle quantum, rather than two per native step. The 1-step setting follows the existing step path and encoding. The default quantum is 16 steps and the maximum is 64; the lifetime limits do not refresh.

A quantum ends at the first response, transient I/O refusal, error or step boundary. It never prepares another request, retries a transient error internally, or waits for readiness. The caller still supplies bounded/nonblocking I/O and schedules subsequent calls. This removes repeated durability work within a progressing exchange, not the synchronous source/storage latency or the need for readiness scheduling. No throughput or latency benchmark has been executed.

Before I/O, the saved absolute ceiling bounds the native calls, write chunks and one response. If completion acknowledgment is lost, recovery consumes the entire ceiling and preserves the exact unresolved command. Reopening the same image neither refills work nor charges it twice. A larger quantum can lose more unused allowance on crash; that conservative charge is the explicit tradeoff for fewer replacements. Reservations are not completed work or evidence that any request reached the server. `FileClientInspection::reserved_drive` reports the selected batch separately from actual counters and the existing `reserved_work` projection.

Version-two `FACDISK` images are used only for pending multi-step reservations. They retain the original image fields plus an explicit final big-endian u64 step bound, and require a present bounded reservation and 2–64 steps. Truncation, trailing bytes, changed domain/limits/path, rollback below the external floor, invalid ceilings and version downgrade refuse before cleanup. The original client archive, one-step images, preparation and completed images remain byte-identical. Older readers reject pending version-two images rather than misreading them as ordinary single-step reservations. The server journal and wire commands are unchanged.

The owner becomes unavailable before intent encoding/storage and stays unavailable across I/O and completion encoding/storage. No response escapes a failed completion, and a caught unwind cannot repeat the batch. Exact retries still reacquire the original server ticket; an altered request cannot replace retained bytes. No published effect is undone by client loss, and stream finish remains a separately approved operation. There is no alternate outcome evaluator, new authority ledger, automatic reconnect or background task.

Six unit regression functions include fifteen original Store fault barriers across intent, partial completion and received-response completion; actual step-oracle parity; a scripted large exchange requiring one durability pair instead of a pair per step; capacity exhaustion before I/O; caught write/read interruption; legacy/version-two decoding; and retained lifetime exhaustion. Two integration functions use actual Unix sockets and the original full-input congress, separate human approval, publication and endpoint reconciliation. They cover original-key recovery after a lost reply and two Unicode-capable messages plus a separately reviewed finish. These are added assertions, not passing executions. The remote-only RCH attempts stop before compilation because `rch` is absent; compilation, rustfmt, Clippy, tests and production performance remain unverified. No dependency, previous assertion, Beads state or qualification gate changes.
