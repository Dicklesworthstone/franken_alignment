# Drive external actor processes through registered evidence and native stops

`drive_actor_process_from_file` and `drive_stream_process_from_file` connect an `ActorProcess` to its exact original `FileActorSupervisor<FileOversight>` or `FileSupervisedDriver`. These methods use the existing actor wire, source-acquisition helper, sealed file readers and one-use intake slot. The stream variant validates the complete original binary intent before source/clock access. Neither variant replaces the request allocator, consistency observer, congress, human key, publication guard or endpoint reconciliation. There is no new wire verb or source provider.

Gateway identity is checked before process polling, termination, source access or protocol work. Invalid socket budgets also refuse before work. Complete NEW requests invoke the original fresh source read and post-read lease check. Fragments, malformed stream intents, poll/cancel and exact/conflicting retries retain their read-free behavior. `FileActorProcessDrive` retains the actual socket result, complete-frame source reports, process status and withdrawal reason separately. An acquired source is not a successful submission; an actor reply is not an effect permit.

Before driving ingress, an acknowledged native terminal stop closes the socket and requests direct-child termination without needing a clock or source. A faulted or inaccessible original owner causes a separately labeled OwnerUnavailable withdrawal: it is NOT a claim that a native stop committed. The same check runs after socket work so a journal failure DURING intake cannot leave that actor ingress active. A caught intake unwind is latched by ActorProcess; the next supervised step withdraws it without replaying the interrupted request. No background work occurs; the host must schedule these operations, retain the process and poll until reaped. The integration does not independently detect a crashed/unscheduled supervisor or terminate process descendants.

Stopping the actor never refunds a charge, fabricates a finish marker, or cancels an effect. Native `request_stop` and `progress_stop` retain their separate meanings. A published request remains outcome-unknown until the original endpoint receipt is reconciled. An unresolved dispatch stays charged after direct-child termination. The driver methods retain their existing helper-reaping behavior and keep all human/topology/identity/prediction/evaluation roles separate from the actor.

Five public regression functions, using a separately re-executed real child-client fixture, cover source-backed stream publication and source-free retry/poll after file disappearance; malformed stream and foreign-owner refusals without reads or process intervention; native stopping with both executed and unexecuted original dispatches followed by native draining; actual staged-write failure and a caught clock interruption without request replay; and the equivalent raw-actor source/congress/human/publication path. The fixtures are analytic clients, not trained models or sandbox qualification. A compile-fail doctest rejects report-to-permit conversion. All added assertions remain unexecuted here.

Targeted RCH and full xtask gate attempts exited 127 before compilation because rch is unavailable. Compilation, rustfmt, Clippy, unit/integration tests and doctests remain unverified. No dependency, domain journal encoding, previous assertion, Beads status or production qualification changes. The host still must establish ambient-authority isolation, executable/source integrity, clock provenance, descriptor policy and private diagnostic routing. Socket budgets do not bound synchronous spawning, source reads, journal replay or disk latency.
