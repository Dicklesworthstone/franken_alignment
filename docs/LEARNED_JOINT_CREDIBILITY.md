# Joint credibility control for learned publication

The original learned generation can require the existing held-out joint
credibility guard. When independently supplied campaign evidence proposes new
helper weights, the native controller compares the baseline and the actual
capped candidate on the same sealed cases through the original Congress
reducer. Improving individual helper scores cannot excuse a newly missed
violation or a newly false-stopped safe case.

This is a scoped FA-105 integration under plan sections 9.4, 9.7, 9.9 and 22.4,
and the existing learned requalification work item. It connects an existing
native promotion rule to learned generation; it does not establish calibrated
detector quality, independence of scenario origins or evaluator authentication.
The full roadmap and deployment gates remain separate.

## Operator selection

The existing learned commands accept a closed `fa.learned-joint-publication/1`
envelope wherever they accept a learned recipe. The envelope has exactly these
three fields:

| Field | Value |
| --- | --- |
| `schema` | `"fa.learned-joint-publication/1"` |
| `joint` | The complete policy object below. |
| `recipe` | The complete existing `fa.learned-publication/1` through `/6` recipe object, including all its ordinary fields and selected files. This is an object, not a filename. |

For example, the `joint` object has this shape:

```json
{
  "id": 71,
  "generation": 1,
  "minimum_safe_roots": 1,
  "minimum_violation_roots": 2,
  "maximum_escape_ppm": 0,
  "maximum_false_stop_ppm": 0,
  "max_cases": 16,
  "max_member_outcomes": 64
}
```

These values illustrate the format, not calibrated reliability requirements.
Use the independently registered policy and work ceilings for the actual
campaign population. Missing, unknown, duplicate or invalid fields and nested
joint envelopes refuse. The complete document retains the original 64 KiB
limit and aggregate item/string bounds. Only the envelope's additional object
depth is admitted; unwrapped recipes keep their original depth limit.

Creation selects the guard before the first canonical image. Later recipes must
retain the identical original generation and joint policy:

```text
supervise_publication create-learned-generated CONFIG JOINT_FIRST_RECIPE REVIEWER_PROFILE
supervise_publication create-learned-generated CONFIG JOINT_NEXT_RECIPE REVIEWER_PROFILE --after-message PREVIOUS_REQUEST --credibility-activation CAPSULE
supervise_publication create-learned-generated CONFIG JOINT_FINISH_RECIPE REVIEWER_PROFILE --finish-after-message PREVIOUS_REQUEST --credibility-activation CAPSULE
```

The original continuation, request, sidecar and review identities still apply.
The capsule is separately provisioned held-out evidence consumed by the existing
activation operation. It is not placed in the recipe or obtained from an actor.
Initial creation still refuses an activation option; it cannot manufacture prior
campaign history. The existing `--continue-generation` path also supports a
fresh capsule when the original request has not yet been submitted.

Resident sequence entries can each select the envelope. Every entry must retain
the exact same complete generation configuration, including the joint policy
and work ceilings. A mixed sequence refuses before a clock, socket or authority
store is acquired. Explicit resident recovery now reaches the same existing
activation path through the outer command parser:

```text
supervise_publication serve-learned-generated CONFIG JOINT_SEQUENCE REVIEWER_PROFILE --after-message PREVIOUS_REQUEST --credibility-activation CAPSULE
```

Fresh resident creation refuses that option. The original topology selection,
independent history anchor, retained outputs and forecast choices remain
available under their own contracts. Historical recipe loading retains the
joint pin without loading current native helper files; receipt-only and terminal
commands do not read an activation capsule or perform fresh helper review.
The original model, tokenizer, codec and selected forecast assets remain
required to reconstruct the independently supplied generation configuration.

## Independently selected native contract

Before creating the authority store, select the policy on the original
`FileLearnedConfig`:

```rust,ignore
let generation = generation.with_required_held_out_joint(joint_policy)?;
assert_eq!(generation.required_held_out_joint(), Some(joint_policy));
```

The policy is the existing `HeldOutJointPolicy`. Its identity, generation,
minimum safe and violation roots, maximum escape and false-stop rates, and
complete case/member work limits all become part of the exact independently
retained generation configuration. The immutable wrapper preserves the original
model, tokenizer, monitor, prompt, sampling, source, sidecar, predictor and
finite allowances. Wrapper order remains part of exact configuration identity.
Configurations without this selection retain their original bytes and behavior.

The original learned Enable installs the policy through the native credibility
transition in the same candidate image as the numerical owner. Creation returns
no intermediate owner with a missing guard. Duplicate selection, a conflicting
evaluation lane or an already installed held-out policy refuses through the
original bootstrap rules. There is no new weight setter, live policy replacement
or alternate activation operation.

The selected policy constrains later promotion. It is not an activation capsule
and does not declare the baseline committee qualified on future campaign data.
The native baseline remains usable under its original review requirements.

Fresh [unsampled prompt preparation](LEARNED_PROMPT_PREPARATION.md) also accepts
this complete policy, including canonical `identity(joint(recipe))` composition.
The checkpoint retains every selected guard with zero sampled draws and no
effect authority. Preparation still refuses activation: its sequence-zero cut
cannot invent prior early-Hold evidence. The baseline can continue under the
original live reviews, or the existing narrowing/reset workflow can precede a
fresh campaign at its actual resulting cut. Current source, selected identity,
forecast and both publication keys remain separate requirements afterward.

## Activation, continuation and recovery

The existing held-out activation owns all evidence checks and weight derivation.
It still requires exact committee and helper identities, current policy and
control predecessors, bounded evidence age, complete per-stratum observations,
and the original member/cohort influence caps. The joint guard then compares the
actual candidate with the baseline, preserving the original campaign refusal
of duplicate evidence roots and every refusal for incomplete, censored, late or
insufficient evidence.
See [the native held-out joint contract](HELD_OUT_JOINT_GUARD.md).

Ordinary, raw-predictive and owned-predictive learned recovery already require
the independently supplied exact generation configuration before numerical
replay. This includes topology-mediated recovery, receipt reconciliation and
terminal consumers. Omitting the wrapper or changing any policy field cannot
open the new history as a legacy configuration. Existing guard, topology,
history-anchor, reserve and external-floor requirements still apply. A separate
outer joint Enable remains subject to its original profile restrictions.

Full native replay reconstructs activation reports from their original inputs.
The recovery fence invalidates previous qualification and old effect keys. A
historical capsule retry retains its historical result; it cannot restore
current qualification. Fresh activation is a distinct original governance
transition. Neither it nor the joint guard resumes numerical work, refills
forecast or source budgets, forgets sampled draws, refunds unknown effects or
replaces fresh native review and human approval for a later publication.

Receipt-only and terminal recovery do not acquire a new qualification merely
to settle an existing effect or stop the original owner. Their original
restricted consumers and evidence requirements remain in force.

## Governed resident creation

A fresh nonpredictive learned sequence can select the same joint envelope while
serving the independent live policy governor. Use the existing creation inputs:

```text
supervise_publication serve-learned-generated CONFIG JOINT_SEQUENCE REVIEWER_PROFILE \
  --campaign-profile CAMPAIGN_PROFILE \
  --operator-profile OPERATOR_PROFILE --tower-generation 41 \
  --governor-profile GOVERNOR_PROFILE
```

The sequence still requires at least two Messages and may end with Finish.
Every entry must select the identical complete joint policy, including its
identity, generation, both population minima, both rate limits and both work
ceilings. Mixing a guarded entry with an unguarded entry also refuses. These
comparisons use the admitted recipe documents before any model/helper asset is
loaded. The original full loaded-generation and stream comparisons remain in
force afterward.

The original constructor installs the joint guard in the first canonical image,
alongside the independently selected campaigns, source, numerical owner, stream
and terminal reserve. With the existing topology selection it also retains the
original mediated source and publication guards. The complete selection supplies
one original owner and separate governor, operator and human-review custody.

This owner starts with its original baseline committee. Installing the guard
does not constitute held-out activation or invent campaign history. Fresh
creation still refuses `--credibility-activation`. Independent campaign Request
and Approve, followed by the separate operator's policy Promote, can continue
baseline publication under the original native review, current source, selected
publication witnesses and fresh human approval for every Message and Finish.
All original numerical, source, campaign and transport allowances remain finite
and cumulative. Once a later explicit recovery has actually activated held-out
qualification, its normal policy/currentness invalidation rules apply; that
owner cannot fall back to the baseline when qualification becomes stale.

## Governed resident recovery

An explicitly recovered, nonpredictive resident sequence can retain its original
joint guard while serving the independent live policy governor. Select the
existing governed recovery inputs and a fresh activation capsule:

```text
supervise_publication serve-learned-generated CONFIG JOINT_REMAINING_SEQUENCE REVIEWER_PROFILE \
  --after-message PREVIOUS_REQUEST \
  --history-anchor INPUT_ANCHOR --retain-history-anchor NEW_OUTPUT_ANCHOR \
  --operator-profile OPERATOR_PROFILE --tower-generation 42 \
  --governor-profile GOVERNOR_PROFILE --credibility-activation CAPSULE
```

Use `--continue-generation` for an original unsubmitted generation. Every recipe
must carry the outer `fa.learned-recovery-policy/2` envelope containing the full
current effective policy and exact original campaign inventory. Its inner joint
envelope retains every original joint-policy field and both work ceilings.
Every entry must agree, and the campaign inventory must match the governor
profile. The original guarded replay checks these complete independent
requirements before its Fence returns fresh human and governor custody. It
cannot install a missing campaign or joint guard during recovery.

With topology selected, the original v2 source checkpoint must match the history
anchor. The capsule must name the actual recovered control sequence and authority
epoch, including the completed source rebind. Activation runs once, before the
first remaining entry's fresh source certification and new numerical generation.
Later Messages and Finish retain that same qualification and check its currentness;
they do not reread the capsule or recover another owner. Every release still
requires its own actor ingress, native/process review and independent human key.

Governor Request and Approve operate on retained campaign evidence and supply no
qualification or effect permission. A subsequent policy Promote invalidates
qualification for the previous policy. The sequence has no automatic or
per-entry requalification: the next boundary requiring current qualification
refuses through the existing failure/Stop handling. The initial capsule is not
reapplied after a policy change and cannot reopen a stopped history.

The capsule's canonical path cannot be the governor's socket path, including
aliases through existing parent directories and paths whose final file does not
yet exist. This custody check precedes model/helper assets, the invocation clock
and authority-store opening. Raw and owned forecast selections remain outside
governed recovery because policy promotion cannot rebind their original
policy-generation registrations. Governed learned creation retains the baseline
contract above and still refuses activation. See
[governed learned recovery](LIVE_POLICY_GOVERNOR.md#recover-a-governed-learned-sequence)
for the complete role, campaign and numerical-replay profiles.

## Verification boundary

The governed resident creation addition has independent source review and
qualified-nightly Rust syntax parsing. Its eight
new regression functions cover actual fixture Message/Message/Finish across
independent promotion in plain and mediated owners, paired human rejection,
final source failure, complete policy equality before assets, direct admission
boundaries and original atomic baseline construction. Required RCH compilation
and runtime execution remain pending; these sources do not establish calibrated
helper reliability or qualify the new live-governor composition.

The governed resident recovery addition has independent source review and Rust
2024 syntax parsing; its required RCH compilation and runtime execution remain
pending. Authored regressions cover plain and mediated Message/Finish recovery,
separate governor approval and human rejection, historical-capsule refusal,
policy promotion invalidating qualification, exact original guards and capsule
pathname custody. The execution results below describe the earlier joint
integration and do not qualify this added live-governor composition.

All five public `learned_held_out_joint` functions and all fifteen public
`held_out_joint` functions pass. They exercise native configuration, creation,
activation and recovery with independent permitted and refused controls,
including actual learned output and two-key publication, every policy field,
all three mediated predictor lanes and failed-installation rollback.

All sixteen selected operator functions pass: six new joint-policy regressions,
seven existing learned-qualification regressions and three outer-parser cases.
The new lifecycle uses actual learned generation, native helper inference and
human review across all three forecast modes. A marginally qualified reduction
from helper weights 5 to 4 loses two complementary vetoes under the frozen
Congress thresholds; the joint requirement refuses before another request,
token, forecast, charge or journal change. A closely matched nonregressing
capsule then reaches the second confirmed publication. The other new cases
cover all six legacy recipe versions, closed parsing, exact resident selection,
full command routing, every policy field before recovery cleanup, and offline
receipt/terminal recovery.

Runtime execution uses `nightly-2026-09-08` and its official Cranelift backend,
one compiler thread and disabled MIR optimization. The public targets are
unmodified Cargo targets. The operator harness changes only unrelated test
registration in a disposable copy: all bodies, assertions, fixtures and
production remain, selected files are byte-identical and source hashes are
checked before and after execution. Its successful run uses a 32 MiB libtest
thread stack; the unchanged binary had overflowed the default stack in an
existing lifecycle case. This is scoped runtime evidence, not a full operator
suite or release qualification.

Earlier attempts remain recorded: two complete-library builds and a standard
compiler check were OOM-killed; an operator preparation stopped when its frozen
input check detected an intervening public-test correction. Actual execution
also exposed two older fixtures that incorrectly tried to seal duplicate roots
and a new assertion that counted the existing four-byte blob prefix as eight.
Those fixtures were corrected without changing production admission, binary
encoding, scoring, guards or finite limits. Independent review confirmed the
corrected controls. Synthetic labels test enforcement and do not measure real
helper reliability.

The complete unmodified operator test source and both public targets also pass
the standard qualified compiler's Cargo check. No test-registration changes
are used for that compiler check.

The standard full xtask command compiles and executes, then refuses the existing
dependency graph before formatting, Clippy or tests. Full FA-105, dependency
admission and release qualification remain open.
