# Atomic predictive startup and exact-contract recovery

`FileOversight::create_predictive_guarded` installs the current native `FileConsistencyConfig` together with all requested existing guards and optional independent evaluation in the first canonical image. It reuses `PreparedGuardedBootstrap`, the original perimeter resolver and native enable transitions. There is no intermediate owner. Only the original acknowledged Store replacement returns `FilePredictiveRoles`, which includes a separately held `FileConsistencyObserver`, the existing oversight role bundle and an optional independent evaluator. No forecast, calibrated score, clock or effect approval is invented.

`open_predictive_guarded` compares exact predictor presence and configuration bytes (coefficients, calibration table, category, identities and lifetime bounds), optional evaluation, numerical configuration and stop policy before historical execution. Full semantic replay and all remaining guard, policy, credential and independently retained counter-floor checks precede cleanup and the single original recovery fence. Old observers, evaluators, tickets and effect approvals cannot be reused. At a clean boundary the native evidence, source sequence and consumed prediction budget survive; a fresh observer can forecast only with fresh time and a newer source sequence. An unanswered forecast remains retained and becomes lost coverage. Recovery cannot choose to omit its unknown outcome or reset lifetime evidence.

`read_predictive_consistency` validates one whole canonical image beside a locked/faulted owner and returns its publication cut, original likelihood evidence and optional credibility report. It acquires no writer lock, removes no pending file, observes no clock and returns no role. Reading an unanswered forecast is historical inspection, not a recovery transition: it does not itself mark coverage lost. Full historical numerical replay is additional work outside a per-token budget.

Existing guarded and evaluated-guarded interfaces now require prediction to be absent, including before numerical replay. They cannot silently accept an unchecked predictor contract. Their public struct layouts and original positive behavior are unchanged. Legacy generic recovery retains its separately documented behavior. Predictor configuration equality is not authentication, calibrated likelihood is an external assumption, and history floors do not detect equal-counter forks or external gaps never recorded in the canonical journal.

Five public regression functions cover fresh observer/evaluator custody after one reopen with retained labels and evidence and a second actual two-key publication; pending-outcome recovery without rearming; exact prediction/evaluation/independent-floor mismatches with preserved staged/canonical bytes; passive inspection beside faulted storage and malformed suffixes; and invalid native bootstrap with valid controls. Three unit functions cover ten original Store barrier scenarios across first publication and pending-forecast recovery, plus duplicate and absent predictor preflight. One compile-fail doctest rejects snapshot-to-permit conversion. These are added sources, not passing execution results.

The work adapts the previously prepared predictive-recovery change to the newer consistency implementation at cced87e8003914a180af5fca5d49c7a9f5f193e4, preserving its observer custody, native proposal results and event encodings. No replacement request allocator, predictor, evidence process or authority ledger is introduced. The RCH invocation exited 127 before compilation because rch is absent. Rust compilation, rustfmt, Clippy, tests and doctests remain unverified. No dependencies, existing assertions, Beads states or production qualification gates are changed.
