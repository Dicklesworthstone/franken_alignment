# Design registries

These are versioned planning inputs, not machine-certified production authority.

`invariants.json` records 40 exact obligations and scope/negative tests. `roadmap.json` sequences 143 packets. `founding_concordance.json` is the normative map from the two founding essays (38 ideas, 9 syntheses, 67 engineering additions, 8 non-literal imports) to sections, invariants, hypotheses and packets. `experiments.json` is the preregistration ledger (no protocol is preregistered yet). `system_map.json` states the nine-layer tower (objects, verbs, boundary invariants, packets per layer) and `vocabulary.json` the address scheme, nouns, verbs with authority/class/idempotency/cost, reason codes, Knowledge variants and retired verbs; packet FA-132 keeps both checked against the plan, the agent guide and the beads. `foundation_audit.json` pins the code review; `sources.json` retains founding/earlier research provenance with head-commit pins. `dependency_policy.json` and `release_readiness.json` explicitly admit no production foundation closure or release yet; the latter records the single local quality-gate execution of 2026-09-06. `claims.json`, `slo.json` and `operation_costs.json` retain the claim/cost model; any new production operation needs a registry row before activation.

Concordance coverage is fail-closed: roots match only `FI-A\d\d`, `FI-I\d\d`, or `FS-\d\d`; every plan heading from §2, invariant, hypothesis and roadmap packet needs a direct typed root. A hypothesis object (`H1`) and its heading key (`§20#H1. …`) are separate coverage. Heading keys canonicalize `N[.M].? …` or `§N[.M].? …` to `§N[.M]`; an unnumbered `###` is `§<nearest numbered section>#<trimmed, whitespace-collapsed exact text>`, preserving case and punctuation. Fenced-code headings are ignored and duplicate keys fail. An invariant root may guide, but never automatically substitute for, a packet mapping; no parent, dependency, sibling, status or prose fallback exists. §§2, 22.6 and 25 are required coverage; engineering additions may cover them without excluding a directly served founding idea or synthesis. See `docs/FOUNDING_IDEAS.md` for the complete normative rules.

Preparation validates parseability, IDs, dependency acyclicity, file/test-symbol references and selected cross-file consistency. Those results are recorded in the validation report. The included Rust xtask currently enforces only its documented initial dependency/source inventory and actual local compilation/test commands; it is not a complete JSON/schema/registry validator. Implement the full owned registry compiler before production activation.

No missing checker is a passed checker. The reference tests were unexecuted in the revision 0.2 preparation history and were executed on one operator host on 2026-09-06 (see `artifacts/execution/`); a new run is required for new code.

## Current-prose consistency contract

`xtask prose-check` examines only current declarations. In `README.md`, it requires one `## Determinism, verification & governance` section and its unique `**Reference Oracle.**`, `**Registered Invariants.**`, and `**Falsifiable Research Hypotheses.**` anchors. In `IMPLEMENTATION_STATUS.md`, it requires the single unfenced `Current execution evidence: [receipt](artifacts/execution/<name>-receipt.json).` declaration and the unique current `Surface` table rows for `Rust test functions`, `Machine-readable registries`, and `Founding-ideas concordance`. The current table is selected only before the first heading beginning `## Execution facts recorded `; repeated `Surface` headers after that historical boundary are deliberately excluded and remain historical evidence. Registry counts are read, rather than copied into the checker, from the typed `founding_ideas`, `syntheses`, and `engineering_additions` arrays in the concordance, the `invariants` array, the claims array, and the roadmap `packets` array.

The named receipt must be `fa.execution_receipt/1` with a zero exit code, passed format and check fields, an allowed passed Clippy field, zero failed tests, and a nonzero `total_passed` exactly equal to the sum of its reference-unit, reference-integration, xtask, and doctest fields. Those comparisons establish declaration consistency, not authenticated execution. README and status input is taken from unfenced Markdown; founding-table section references use the shared plan-heading scanner. The checker prints an operator SHA-256 for each prose input, and an outer source freeze remains required; neither an operator hash nor a retained receipt binds old execution evidence to new source.

Run the complete gate with `RCH_REQUIRE_REMOTE=1 rch exec --base HEAD --clean-overlay --no-overlay -- cargo +nightly-2026-09-07 run --locked -p xtask -- check`; run only this declaration check with `RCH_REQUIRE_REMOTE=1 rch exec --base HEAD --clean-overlay --no-overlay -- cargo +nightly-2026-09-07 run --locked -p xtask -- prose-check`. After a newly executed test receipt is retained, a standalone prose refresh can check the updated current declarations against that named receipt without rerunning the full gate. It does not grant the old receipt execution credit to changed source; new source still requires its own frozen, qualified execution evidence.

## System-map and vocabulary consistency contract (FA-132)

This is a static registry enabler, not an implementation of an agent command, conformance suite, or production authority. Its bounded inputs are `registry/system_map.json`, `registry/vocabulary.json`, `registry/invariants.json`, `registry/roadmap.json`, `COMPREHENSIVE_PLAN_FOR_THE_DESIGN_OF_FRANKENALIGNMENT.md`, `README.md`, `docs/AGENT_GUIDE.md`, `docs/SYSTEM_MAP.md`, and the read-only `.beads/issues.jsonl`. The map must contain the unique L0 through L8 layers, with nonempty question, objects, verbs, conformance-suite declaration, and unique object names; its normative and per-layer plan-section keys use the shared concordance heading scanner, while every boundary invariant and packet, including `checker_packet`, must exist in its typed registry. A declared or planned suite is never treated as executed.

Each map-listed verb must be registered. Each registered verb must have nonempty authority, class, idempotency, cost class, and response; the class is `read`, `rehearsal`, or `mutation`. `layers[*].verbs` records cross-layer access, while `vocabulary.verbs[*].layer` records canonical ownership or an allowed layer range/list: repeated cross-layer reads such as `get`, `when`, and `explain`, and descriptors such as `L0-L2` or `L3/L6`, are intentional and must not be rejected by one-to-one layer equality. Command scanning is limited to `README.md` and `docs/AGENT_GUIDE.md`: recognize `fa <verb>` in inline code, fenced code, and Markdown table cells; split a command selector such as `fa promote|rotate` into both registered verbs; ignore the literal template `fa <verb>`. A recognized command must be registered and must not be retired.

For these three agent-facing documents, a concrete `fa://tenant/kind/id[@generation]` address must use a registered noun; `<tenant>/<kind>/<id>` and ellipsis forms are templates, not concrete addresses. Both registries must list exactly the six constitutional Knowledge variants. Qualified `Knowledge::Variant` names and explicitly labeled Knowledge variant lists are checked against those sets. The six known bare constructors are accepted; an arbitrary domain constructor is not classified as Knowledge merely because it begins with a capital letter. The type parameter in `Knowledge<Object>` names a payload, not a variant. This bounded syntax check cannot infer an unqualified token's Rust type from general prose. The nonempty reason-code list in the uniquely anchored plan §17.3 subsection must be a subset of registered reason codes. Finally, parse each nonblank `.beads/issues.jsonl` line as JSON, reject malformed records, ignore tombstones, and require exactly one remaining issue description line `- Roadmap packet: <checker_packet>`; that is the read-only checker-epic link, not comprehensive bead/roadmap coverage. These rules fail closed on absent, duplicate, malformed, or dangling input within the declared grammar and do not write an artifact.
